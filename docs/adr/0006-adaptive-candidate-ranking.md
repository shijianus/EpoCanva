# ADR 0006 — 自适应候选排序：有界特征、原样硬分层、语言锁存

## 状态

Accepted（原型）。实现：`engine/ranking/adaptive_ranker.{h,cc}`；
测试：`tests/adaptive_ranking`（13 条 CTest）。
**未接进 `engine/backend` 或 TSF 产品路径**，因此不构成"产品已会智能排序"。

## 背景

现有排序把若干未标定项直接相加：

- `engine/lexical_service/lexical_service.cc:313-325`：
  `log1p(static) + 0.75*log1p(learned) + 1.25*log1p(context)`；
- `engine/backend/backend_api.cc:792-797`：`match_log_score + Σ token log-probability`，
  且丢弃 lexical 的 `row.score` 后重建；
- 中文 `-0.05*rime_ordinal`，日文 `-cost/1000`。

问题不是"数值不对"，而是：

1. 特征没有声明区间，一个极端值可以压过所有其他信号；
2. 没有原样候选的硬保证（虽然有候选 0 恒为原文的约定，但那是生成顺序，不是排序保证）；
3. 没有语言混合的稳定性机制；
4. 权重散落在三个文件里，无法被离线评测替换。

## 决策

1. **分数单位固定为"排序点"**：可加的、类似对数似然的标量，**不是概率**，
   跨语言不可直接比较。
2. **每个特征先钳制到声明区间再加权**：
   `prefix∈[0,1]`、`static∈[0,1]`、`context∈[-20,0]`、`personal∈[0,2]`、
   `negative∈[-1.5,0]`、`spelling∈[-1,0]`、`language∈[-1,0]`。
3. **原样候选是硬分层，不是权重**：`tier 0` 的候选（文本与输入按 ASCII 大小写不敏感
   完全相等）永远排在 `tier 1` 之前。任何模型、个人偏好或负反馈都不能把用户自己
   输入的文本挤出首位。
4. **`context_logp = 0` 定义为"没有模型证据"**。无模型时所有 context 为 0，
   排序退化为 prefix + static + 个人偏好，仍然有定义、可测试。
5. **自动语言识别锁存**：连续 N 次（默认 3）相同观察才切换；用户显式选择的语言
   只承受有界语言项（`weights.language`），不是绝对否决。
6. **拒绝而非截断**：候选超过 64 条、输入超过 256 字节、权重越界或非有限、
   UTF-8 非法，一律返回明确状态且不产生部分顺序。
7. **确定性**：总分相同按输入序号；重复查询必须逐位相同。
8. **去重按显示文本精确字节**，保留最高分条目。
9. **权重是参数**：`Weights` 可按语言替换，由离线评测决定。当前默认值是工程默认值，
   **没有评测，不得称为已校准**。

## 备选方案与未采纳原因

| 方案 | 未采纳原因 |
| --- | --- |
| 直接改 `backend_api.cc` 的现有分数 | 56 项后端测试依赖当前排序；会破坏既有证据，且属于一次性推倒已通过测试的实现 |
| 用 softmax 概率作为统一分数 | 各语言模型的分词与词表不同，概率不可比；需要额外校准集 |
| 把原样候选只作为一个权重项 | 权重可被更大的模型分数压过，违反"原文优先" |
| 自动识别语言直接决定候选栏 | 会产生抖动；用户显式选择必须优先 |
| 超过上限时截断并返回部分结果 | 静默截断会隐藏真实状态；调用方无法区分"没有更多"与"被丢弃" |
| 引入重排序学习（LTR）模型 | 没有评测数据与授权，先做可解释的有界基线 |

## 后果

**正面**

- 特征、区间、单位、来源都显式，后续接模型时不需要重写排序层。
- 原样优先成为结构保证，不依赖调用顺序。
- 无模型路径有独立测试，满足"不装模型也能用"的产品要求。
- 语言混合的抖动有可测试的机制（锁存 + 有界语言项）。

**负面 / 成本**

- 默认权重未校准，混合权重排序只能保证一致性，不能保证质量。
- 硬分层使"用户打的错词"也永远第一；这是刻意取舍：宁可保留原文，也不擅自替换。
- 与现有 `backend_api.cc` 的分数并存，接线时必须删除重复计分，否则同一特征会被算两次。

## 重新评估条件

1. 需要跨语言比较绝对质量时，必须引入校准集并替换 `DefaultWeights`。
2. 接入后端后若发现现有 lexical `row.score` 与新分数重复计分，先删除旧项再谈权重。
3. 需要"错词也允许被纠正到首位"时，重新评估硬分层——但那会改变"原文优先"的产品原则，
   必须单独决策。
