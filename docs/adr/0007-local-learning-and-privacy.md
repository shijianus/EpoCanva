# ADR 0007 — 本地学习：事件类型即隐私边界

## 状态

Accepted。事件语义实现：`engine/ranking/learning_events.{h,cc}`（内存，未持久化）；
存储层实现：`engine/data_store/learning_store.{h,cc}` 与
`windows_learning_repository.{h,cc}`。产品路径**未启用**。

## 背景

现有学习存储只有 ID 与计数（`learning_store.h:51-61`），存在四个产品级缺口：

1. **没有负反馈**：用户明确拒绝后，候选顺序不会变差。
2. **没有时间衰减**：早期偏好永久有效，长期使用会"越用越偏"。
3. **没有用户覆盖字段**：手动添加的词与推断出的偏好无法区分。
4. **产品路径关闭**：`unified_engine_backend.cc:198` 固定 `learning_enabled = 0`。

同时必须避免一个常见但错误的做法：把退格当作负反馈。退格可能表示修改句子、
删标点、删段落、改语法、重新输入或纠正错误。

## 决策

1. **学习事件只用可归属的显式动作表达**：
   `kSelected`（明确点击/快捷键选择）、`kRejected`（明确拒绝）、
   `kSuperseded`（同一菜单里选了别的，弱负反馈）、
   `kManualWordAdded`、`kManualWordRemoved`。
2. **API 里不存在按键、普通提交或退格事件类型。** 删除无法降低分数，
   因为类型系统无法表达。这是结构约束，不是注释约定。
3. **每个候选级事件必须带 `generation` 与 `attributable`**。
   代际不匹配 → `kIgnoredStale`；未证明归属 → `kIgnoredUnattributable`。
   两者都不写状态。
4. **隐私在写入侧拒绝**：`kSensitive` → 拒绝；`kUnknown` → 拒绝。
   未分类不按正常处理。
5. **正负都饱和**：正向 ≤ 2.0，负向 ≤ 1.5。第三次与第五十次拒绝结果相同，
   噪声不能无限惩罚。
6. **半衰期衰减**：默认 1000 tick，`tick` 的单位由调用方定义并保持不变；
   模型内部不解释为墙钟时间，`AdvanceTo` 不接受时间倒流。
7. **容量 512 条**，超限优先淘汰推断条目，再按最旧更新与最小序号确定性淘汰。
8. **关闭学习停止写入但保留既有偏好**；`Clear()` 才是显式遗忘。
9. **持久化不属于本层**。`LearningEventModel` 不写文件；持久化必须复用
   `engine/data_store` 的原子写、隐私回调与 schema 迁移，禁止另起文件格式。

## 备选方案与未采纳原因

| 方案 | 未采纳原因 |
| --- | --- |
| 退格/删除即扣分 | 无法证明归属，会造成系统性误惩罚；规格明确禁止 |
| 普通提交即正反馈 | 用户提交原文不等于喜欢某个候选；会把"没选"当成"选了" |
| 用显示文本作为偏好键 | 文本会变（大小写、形态），且不利于去重与隐私最小化 |
| 无上限累加计数 | 一次误触序列可以永久改变排序 |
| 无衰减的永久偏好 | 长期使用后早期偏好压过当前语境 |
| 在本层直接写 SQLite/文件 | 绕过已有原子写、权限回调与迁移；两套存储格式必然分叉 |

## 后果

**正面**

- "不得按退格扣分"变成编译期无法表达的 API 形状，而不是审核时才发现的错误。
- 隐私拒绝、代际校验、归因校验集中在一条路径，平台层只需提供事实。
- 饱和与衰减让排序对噪声鲁棒。
- 与现有 `LearningStore` 的隐私分类（`kUnknown/kNormal/kSensitive`）一致，
  未来合并时不需要两套枚举。

**负面 / 成本**

- 事件模型与存储层目前是**两套数据结构**：事件带时间戳与负向/手动词条，
  存储只有正计数。合并需要 schema v3 与迁移。
- 隐私判断仍依赖调用方提供正确的 `PrivacyClass`；本层不能验证宿主字段。
- 产品路径关闭意味着以上能力目前只在测试中运行。

## 重新评估条件

1. 产品路径启用持久学习前，必须先解决"字段权限锁覆盖 worker 全程"的问题
   （已在 `docs/reports/ime-prediction-audit.md` 登记）。
2. 若要支持"用户主动降低词条优先级"，`kRejected` 需要增加有界的手动负向覆盖，
   届时必须区分"手动"与"推断"，且手动项不被容量淘汰。
3. 若某平台只能提供按键流而无候选点击事件，该平台**不应**启用学习，
   而不是退化为按键推断。
