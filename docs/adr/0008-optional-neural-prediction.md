# ADR 0008 — 神经预测是可选增强，默认不下载、不加载、不推理

## 状态

Accepted（约束）。现状：推理代码存在但未接产品。

## 背景

`engine/neural/lexical_reranker.{h,cc}` 已有真实 llama.cpp 推理：
Qwen2 GGUF 维度/词表校验（`:276-331`）、tokenize、`llama_decode`、
log-softmax 求和、稳定排序（`:355-468`），模型文件 SHA-256 校验（`:289-291`）。
但它：

- 不链接进 `epocanva_backend`（`engine/backend/CMakeLists.txt` 无 neural 目标）；
- 默认不启用（`data/manifests/backend-readiness.json:17` `neural_default_admitted=false`）；
- 没有模型目录、下载器或安装状态机；
- 只在构建期校验模型，没有真实输入法场景的延迟数据。

同时，把大型模型加载进每个宿主进程的 TSF DLL 会同时放大内存、启动时间与攻击面。

## 决策

1. **默认状态三元组**：不下载模型、不加载模型、不进行推理。
   基础输入、统计候选与排序在无模型时完全可用（ADR 0006 §4）。
2. **模型只按用户明确动作获取**：下载前展示来源、大小与许可；支持取消；
   校验 SHA-256；失败不破坏已安装模型；不得静默下载其他模型。
3. **推理不得阻塞原文与基础候选**：原文提交永不等待模型；统计候选先返回；
   模型在后台有界执行。
4. **预测绑定版本**：结果携带 Session 版本与输入版本；用户继续输入后旧预测必须
   取消或丢弃；焦点切换后不得提交旧预测。
5. **模型不得改写已提交文本**，不得默认自动接受预测。
6. **敏感字段不向模型提供上下文**；判断在调用侧完成。
7. **进程边界**：
   - Windows：模型**不得**直接加载进宿主进程内的 TSF DLL；需要独立本地预测进程
     与严格 IPC（当前用户 ACL、仅本机、消息只含完成预测所需文本）。
   - Android：使用应用私有运行环境与独立推理任务。
8. **用途限定**：下一词预测、CJK 下一字/词/短语、有限上下文排序改进、
   专业语境识别、混合语言候选质量。不做聊天、长文生成或云端写作。

## 备选方案与未采纳原因

| 方案 | 未采纳原因 |
| --- | --- |
| 默认内置一个小模型 | 违反"默认不下载/不加载"；体积与冷启动不可接受；分发许可未审 |
| 在 TSF DLL 内直接推理 | 每个宿主进程一份模型；启动与内存不可控；崩溃影响宿主输入 |
| 云端推理 | 直接违反离线与不上传原则 |
| 模型输出直接上屏 | 违反"不得擅自修改已提交文本" |
| 用一个通用聊天模型同时做补全与领域 | 资源与延迟不可行；领域应按 ADR 0009 的共享基座 + 路由处理 |

## 后果

**正面**

- 用户在未选择模型时得到与现在完全一致的行为，没有隐式下载。
- 推理与编辑协议解耦，可以独立评测、独立降级。
- 进程外推理使 Windows 的离线约束更容易审计。

**负面 / 成本**

- 需要额外进程与 IPC，增加延迟与故障模式（必须静默回退）。
- 模型分发、许可与量化格式需要独立审查，尚未开始。

## 重新评估条件

1. 真实设备上 P95 首结果延迟与常驻内存有测量结果后，才谈默认开启或更低端设备策略。
2. 出现可接受的进程外推理方案并能证明崩溃隔离时。
3. 模型许可与量化格式审查完成、模型目录可固定修订时（见 ADR 0010）。
