# ADR 0009 — 多学科领域：单一共享基座 + 领域路由，禁止叠加模型

## 状态

Accepted（约束与目标架构）。**尚未实现**：没有模型基座、没有领域路由、没有领域词表。

## 背景

产品要求用户可选择 General / Computer Science / Biology / Medicine / Mathematics /
Physics / Chemistry / Engineering / Law / Economics / Finance / Literature / History
等领域，并支持跨学科组合（Biology + Computer Science 应理解为生物信息学）。

直觉上"选两个领域就加载两个模型"会带来三个不可接受的结果：

1. 内存随领域数量线性增长；
2. 两套未校准分数机械求和没有语义；
3. 两个模型各自独立生成候选，交叉领域词不会出现。

## 决策

1. **单一共享多语言基础模型**。领域不是模型，是配置。
2. **领域配置是轻量的**：专业术语词库、术语权重、领域上下文特征、领域标签；
   只有在离线评测证明收益显著且资源预算允许时，才考虑 LoRA 一类参数高效适配。
3. **统一领域路由**：路由输出的是领域标签的组合与权重，不是多个候选列表的拼接。
4. **联合候选排序**：领域贡献进入 ADR 0006 的排序层作为一个**有界特征**，
   与其他特征一起钳制、加权、去重、排序。
5. **交叉领域是一等公民**：Biology+CS 的路由结果应包含"生物信息学"类术语交集，
   Medicine+Chemistry 应包含药物化学/生物化学。组合不是两个列表的并集。
6. **跨语言共享概念，不共享表面形式**：领域标签在概念层共享（例如 `medicine`），
   但候选词形、翻译与排序由各语言规则处理。
7. **适配器必须与共享基座版本和 tokenizer 兼容**；不兼容直接拒绝加载。
8. **禁止**：
   - 选 N 个领域就加载 N 个完整模型；
   - 同时运行多套完整模型再拼接候选；
   - 在未校准的分数上机械求和；
   - 因领域数量增加而线性增加内存。
9. 训练专用领域融合模块前，必须先建立可复现的离线基准与数据授权审查，
   **不得**先宣称"组合模型优于单领域"。

## 备选方案与未采纳原因

| 方案 | 未采纳原因 |
| --- | --- |
| 每领域一个完整模型 | 内存线性增长；不可组合；分发体积不可行 |
| 多模型并行 + 分数相加 | 未校准分数无意义；延迟不可控 |
| 用提示词切换领域 | 只在生成式场景有效；输入法需要低延迟候选排序，不是生成 |
| 只做术语表替换 | 只能补词，不能改变上下文排序；但作为第一层实现是合理的起点 |
| 领域即语言（每领域一个 schema） | 会把语言与领域两个正交维度混为一谈 |

## 后果

**正面**

- 领域数量不直接影响内存。
- 交叉领域可以用标签组合与术语交集表达。
- 领域特征进入统一排序，与其他特征一起受区间约束。

**负面 / 成本**

- 需要领域标注数据与路由评测，短期无法交付"智能领域识别"。
- 术语词库的许可与来源必须逐项审查，不能默认可用。

## 重新评估条件

1. 有可复现的领域评测集与授权数据后，才评估 LoRA 或适配器。
2. 若共享基座无法覆盖某语言/领域（例如低资源语言无对应术语），
   允许该语言退回词表 + 统计排序，但必须显式标注能力不完整。
