# Headless backend confirmation and prediction

`engine/include/epocanva_backend.h` retains the Windows x64 C ABI v1 layouts and functions and adds separate v2 profile structures/functions. It does not replace or modify `epocanva_engine.h`. Each engine loads exact local model resources and, when requested, one real Rime runtime. Each session owns one language/input mode, raw input, display preedit, candidate snapshot, pending commit and bounded confirmed context. Multiple profiles can share a language, use different model/catalog resources, or share immutable resources with different keyboard layouts and output modes. A missing converter, unsupported variant or changed profile binding fails explicitly.

Candidate and commit tokens are process-local opaque values. Snapshot tokens invalidate old candidate choices; target identity and generation remain caller-provided facts, not OS capabilities. All offsets/counts labelled UTF-8 bytes refer to the original input or explicitly named output. Candidate ordinals are record numbers, not text offsets. Output buffers are caller-owned and a short buffer produces no partial text copy.

The sequence is explicit: publish a real provider menu; select a token from that snapshot; read the complete commit; acknowledge applied/rejected. Neither selecting, querying size nor copying text learns. A successful applied acknowledgement consumes the event once, advances at most two admitted lexical IDs of static context, and optionally records known-ID counts. Repeated acknowledgement is stale. Storage failure does not falsify a host edit that already succeeded and does not authorize retrying a consumed token. This is an in-process protocol, not crash-durable exactly-once persistence.

Static confirmed context and personal-learning previous ID are distinct. Turning learning off still allows normal-field static language-model prediction. `set_context` imports bounded confirmed preceding text into transient catalog IDs; `confirm_text` consumes a monotonically increasing host event token. Neither persists ordinary text or personal statistics. Unknown/OOV spans and explicit line boundaries break context; a later known suffix does not reconnect to the pre-boundary words. Candidate ACK remains the only personal-learning route. Off-period and imported tokens are never reused later in a personal persisted bigram. Sensitive/Unknown acknowledgements and confirmations clear transient state without persistence, including stale confirmation events for the same target/generation. Each operation checks the current classification; callers must hold the actual permission/field lock across every call that reads personal data or acknowledges learning. The C struct is not a live OS query. The new Windows integration therefore leaves personal persistence disabled until that lock lifetime can be established.

Chinese candidates and commits come from the real compiled Rime schema, not copied fixture lists. Candidate selection uses the captured Rime snapshot and ordinal, preserving that identity when transient context reranks the page; where a schema only confirms a segment, Return is sent once to obtain a real commit. Any remaining raw input and remaining display preedit are carried separately. The Rime public menu does not expose trusted lexical metadata, so those conversion commits do not learn IDs inferred from display text. After host ACK their text may advance transient context only. Japanese candidates combine actual lexical/POS connection costs with model context; only segments also in the admitted prediction catalog have learnable IDs. Raw candidates always have none.

Candidate union uses one conditional language-model log score plus a separate input-match feature; it does not add lexical unigram/personal totals a second time. Equal display text retains the better combined score and deterministic ID tie-break. A verified exact abbreviation key has explicit-match priority before inferred candidates; its probability is not rewritten. Partial explicit keys and model-derived initials are still contextual suggestions. `Decoder::Decode` supports scalar-safe compact initials and separated word prefixes, with explicit work/beam limits. Prefix queries use immutable ranked lexical-range indexes instead of repeatedly scanning irrelevant words.

Chinese compact pinyin initials are a separate bounded source. The backend builds a syllable/character index from the hash-pinned Terra dictionary only for single-character readings, detects whether the raw input is already a legal full-pinyin syllable sequence, and otherwise runs a character-level beam over admitted model IDs. Full pinyin stays Rime-owned. Initialism candidates carry the resolved character IDs, are marked incomplete because the beam/character caps are finite, and are merged by text with Rime candidates; selection commits their composed text through the normal commit/ACK protocol.

`NEXT_UNIT` emits one complete **model lexical token**, not one grapheme, Unicode scalar or UTF-8 byte, and therefore admits terminal punctuation. `NEXT_WORD` is the word-only request: it asks the model for the documented maximum candidate set and drops terminal/punctuation paths before applying the caller's `max_candidates`, so a punctuation token can never occupy a next-word slot. Bounded `CONTINUATION` remains a distinct phrase request. The current Chinese model is character-level; Japanese uses its documented catalog segmentation. None establishes full Unicode grapheme-aware editing. Native Kana, Romaji/Hiragana/Katakana, Korean two-set/native Hangul, Pinyin/Zhuyin and Latin input are explicit modes, not interchangeable enum labels. The four Latin keyboard geometries affect spelling cost; an unknown layout uses neutral costs. Actual operating-system layout coverage and inline CJK composition require separate product acceptance.

Resource loading pins local path components while hashing and loading. UNC/network mappings, redirecting reparse points and offline recall paths are rejected. Weight/model fingerprints bind bytes, not authenticity or data rights. All requested data must already exist; runtime never downloads. No raw input, prompt, token history or committed content is logged or stored as training data. Explicit user learning stores only bounded admitted IDs/counts under the existing protected-DACL transaction layer.

The core retains the known limitations in the backend report: no complete TSF/Android migration, no claim of full Unicode linguistic coverage, no production language-quality guarantee from smoke tests, no final stable release before quality, resource and legal gates are met. Windows in-process code is architecturally offline, not OS network-sandboxed. Android could enforce no network permission by omitting `android.permission.INTERNET`; no Android artifact is delivered here.
