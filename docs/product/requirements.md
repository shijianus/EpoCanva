# EpoCanva 产品需求基线（P0.1）

状态：基线草案，随阶段推进更新。本文只记录**要求与验收原则**，不描述已实现功能。

## 1. 产品定位

EpoCanva 是**以英语体验为最高优先级、覆盖世界主流语言、离线优先、跨平台、具备本机
长期个性化学习能力，并可由用户选择安装轻量神经语言模型进行智能预测的输入平台**。

底座采用 librime，并允许对其做源码级改造；EpoCanva 在其上建立自有引擎门面、
语言/区域/输入方案身份层、平台适配层与语言能力模块。

目标平台：Windows 原生 TSF 输入法（可安装 EXE）与 Android 原生
`InputMethodService`（可安装 APK）。两者共享跨平台语言核心与用户学习算法，
但输入、编辑、权限与 UI 各自实现。

产品**绝不能**强制要求账户、云服务或神经模型才能完成基础打字。以下三件事必须分别成立：

1. 不联网也能完整打字。
2. 不安装任何模型也能给出有用的候选排序。
3. 用户能完全关闭学习或清除学习数据，且不影响打字。

非目标（本产品明确不做）：

- 不做小狼毫（Weasel）或同文（Trime）的换皮发行。二者可作为 librime 在
  Windows/Android 上如何集成的**参考实现**来阅读，但 EpoCanva 必须拥有自有的
  引擎边界、数据格式、更新与安装体验。任何直接沿用其外壳代码而不加改造、
  仅替换名称与皮肤的做法都不满足本要求。
- 不做云输入、不做联网词库同步、不做用户行为上传（见第 5 节）。
- 不做通用聊天机器人、长文生成或云端写作助手（见第 7 节）。
- 不把神经模型放进宿主进程内的 TSF DLL（见第 8 节）。

## 2. 交付产物

| 平台 | 产物 | 形态 |
| --- | --- | --- |
| Windows | 安装包（EXE） | 安装后向系统注册 TSF 文本输入接口组件；普通桌面进程加载的 DLL |
| Android | 应用包（APK） | `InputMethodService` 应用，受 Android 权限模型约束 |

产物必须可在一台干净机器上由文档化步骤重建，构建过程不依赖任何联网下载。

## 3. 语言优先级（固定顺序）

```
English > Chinese > French > Spanish > Japanese > Korean > German > 其余已声明语言
```

机器可读的唯一实现是 `engine/locale/language_tag.cc` 的 `LanguagePriority()`；
`engine/language_packages` 委托调用它。**禁止**再写第二份硬编码语言列表。

- 该顺序决定**研发深度与资源投入的优先级**，也决定冲突时的取舍方向。
- 顺序**不允许**被解释成"低优先级语言可以完全不能输入"。低优先级语言仍必须能
  输入其自身文字；"尚未实现"是状态，不是拒绝输入的理由。
- 顺序是固定的，不接受实现层面的临时重排。

### 3.1 英文能力的最低要求

**禁止**把英文简化成以下任一形态，它们都不构成通过：

1. ASCII 直通（按键直接上屏，不做任何处理）。
2. 只挂一个基于词典的 Translator 当作"英文支持"。
3. 与中文共用同一套拼音式候选逻辑、仅换词库。

英文能力至少需要覆盖（后续阶段逐项细化为可测条目）：

- 词候选与按频率/上下文的排序，以及用户级学习。
- 形态变化：复数、第三人称单数、过去式/-ed、进行时/-ing、所有格、缩写与展开
  （don't / I'm / etc.）。
- 拼写纠错与近似键位（滑动/误触）容错。
- 连写切分（`theprogram` → `the program`）。
- 句首大写、标点智能补全、符号与 emoji 的英文习惯入口。
- 跨字段一致性（同一英文词在不同应用中候选稳定）。

### 3.2 中文多变体与输入方案

中文不是一种输入身份。至少需要以下**独立**的语言/方案标识：

| 标识 | 含义 |
| --- | --- |
| `zh-Hans-CN` | 简体中文（中国大陆） |
| `zh-Hant-TW` | 繁体中文（台湾） |
| `zh-Hant-HK` | 繁体中文（香港） |
| `yue-Hant-HK` | 粤语（香港） |

输入方案架构必须能接入：全拼、双拼、注音、仓颉、五笔、粤拼，以及后续方案。
本阶段不要求全部完成，但每条路径必须有明确的实现状态和接入契约。

**禁止**把简繁转换认定为完整的中文地区变体支持。转换是字形映射，不是地区词表、
地区用词习惯或地区输入方案。

### 3.3 其余主流语言

首批基础覆盖清单（身份与优先级必须存在，实现可以分阶段）：

```
en zh fr es ja ko de pt it ru ar hi id vi th tr nl pl uk bn fa ur he el sv cs ro sw
```

地区与文字变体使用 BCP 47 风格标签，例如 `en-US`/`en-GB`、`fr-FR`/`fr-CA`、
`es-ES`/`es-MX`、`pt-BR`/`pt-PT`、`de-DE`/`de-AT`/`de-CH`。

**不得为了凑语言数量只注册名称。** 每条语言的基础支持至少需要评估：

1. 正确的原始文字输入。
2. 必要的组合、变音符号或文字转换。
3. 基础候选与本地排序能力。
4. 语言特定的大小写、词界及标点处理。
5. 本地偏好学习的可扩展性。
6. 不安装 AI 模型时的可用程度。
7. 特殊文字系统和双向文字边界。
8. 可执行测试。

没有完整词库或转换引擎的语言必须诚实标为基础能力不完整。

### 3.4 Locale/Profile 注册机制

- 语言身份由 `engine/locale` 统一负责：BCP 47 子集解析、规范化、
  lookup 匹配、默认文字、RTL 判定。
- 一个语言标签对应一个 profile，profile 内部可以有多条输入方案。
- 输入方案有三级实现状态：`kImplemented`（有真实代码与本地证据）、
  `kUnverified`（有资源但无端到端证据）、`kAbsent`。
  `kImplemented` 必须指向一个真实存在的本地证据路径；没有证据的"已实现"注册会被拒绝。
- 解析到多个 profile（如只给 `zh`）时返回**歧义**，由用户或调用方补充 script/region，
  不允许静默猜测简繁。
- 没有引擎的语言没有 profile 条目，解析返回"无 profile"。这是诚实状态，
  不是错误处理缺陷。

## 4. 架构原则

- 平台适配层（Windows TSF / Android IME）与引擎之间必须有**自有 C ABI** 边界；
  librime 的类型、回调与生命周期约定不得越过适配边界。
- Session/编辑协议必须显式定义：组合缓冲、preedit 区间、上屏文本、光标锚点、
  撤销与"提交后回改"能力，且所有偏移**标明计量单位**（UTF-8 字节 / UTF-16 代码单元 /
  字素簇 / 屏幕列）。Windows 侧以 UTF-16 为主，librime 侧以 UTF-8 为主，转换只允许发生在
  适配层。
- 英文能力是引擎内的独立模块，而不是词库配置项。
- 学习数据与用户词库属于用户隐私数据，边界与持久化格式由独立层负责（见威胁模型）。
- **不得**简单复制英文 Translator 再为每种语言替换词表。共享的是框架、候选契约、
  排序与学习；语言特定的是分词、形态、转换与候选生成。
- 语言核心不得直接依赖 Windows COM。TSF 与未来 Android IME 使用同一业务契约。

### 4.1 默认多语言智能排序（无模型也必须可用）

这是默认能力，不是可选增强。不下载、不加载任何神经模型时，EpoCanva 仍必须依据
语言、文字系统、词表、基础上下文与用户偏好给出有用候选。

排序特征必须显式声明单位与区间，至少覆盖：

- 语言与文字系统匹配；
- 前缀匹配质量；
- 正规化后的词形匹配；
- 词表基础权重（**Alt12Dicts 的收录权重不是语料频率**，不得当作语言概率）；
- 真实频率资料（仅在许可与来源可靠时）；
- N-gram 上下文概率；
- 用户长期选择偏好；
- 明确拒绝或可靠纠正产生的负反馈；
- 时间衰减；
- 领域相关性；
- 原样候选保护；
- 可选神经模型分数。

要求：

- 每个特征先钳制到声明区间再加权；**禁止**把未标定的原始计数直接相加后宣称完成智能排序。
- 必须存在"无模型回退"路径，且该路径的排序有定义、可测试。
- 原样候选是硬分层：任何分数都不得把用户自己输入的文本挤出首位。
- 输入超限、非法 UTF-8、非法权重必须**拒绝**，不得静默截断或产生部分顺序。
- 权重是参数，必须可被离线评测替换；没有评测就不得称为"已校准"。

### 4.2 语言混合

- 允许多候选源，但必须经统一规范化、去重与排序。
- 用户显式选择的语言优先；自动识别只能作为**有界**辅助。
- 自动识别必须锁存：连续 N 次一致观察才切换，避免候选栏抖动。
- 至少需要覆盖 English+Chinese、English+French、English+Spanish、
  English+Japanese、English+Korean、Chinese+English+专业术语 的组合测试。
- 混合状态下排序必须稳定；同一输入重复查询不得产生不同顺序。

### 4.3 本地长期偏好学习

这是正式产品必需能力，不是装饰功能。

正反馈只允许来自：

- 用户明确点击候选；
- 用户通过快捷键明确选择候选；
- 同一语言环境下重复选择某个词形；
- 用户主动添加个人词条；
- 用户明确设置某个候选优先。

负反馈只允许来自：

- 用户明确拒绝某条建议；
- 用户选择其他候选替代原建议（弱负反馈）；
- 可证明属于同一编辑会话、且能归属到具体候选的纠正；
- 用户主动降低词条优先级或删除个人词条。

**禁止"按一次退格就扣分"。** 退格可以表示修改句子、删标点、删段落、改语法、
重新输入或纠正错误；无法证明事件归属时**不学习**。学习事件的类型定义里不得出现
按键或普通提交，使这条规则成为结构约束而不是口头约定。

数据模型至少包含：Language/Profile ID、candidate identity、normalized lexical identity、
正向摘要、负向摘要、最后更新时间、衰减元数据、用户覆盖、schema version。
**不持久化**完整击键序列或原始上下文；默认不记录宿主应用名、窗口标题或字段内容。

存储要求：本地保护（Windows DPAPI / Android Keystore 等）、原子写入与崩溃恢复、
数据迁移、存储上限、过期与衰减、用户清除、关闭学习、损坏后安全退化、
备份/导入的显式授权。**不得**声称本地加密能防范已控制设备的恶意软件。

默认允许普通非敏感输入的本地学习，但必须有清晰开关与清除入口。
密码、一次性验证码、平台标记的敏感字段、用户隐私模式、以及无法可靠确认安全的字段，
一律禁止学习与持久化，也禁止把上下文交给神经预测器。

### 4.4 可选轻量神经预测

- **默认不下载模型、默认不加载神经模型、默认不进行神经推理。**
- AI 预测属于增强功能，不得成为基础输入依赖。
- 用途限定为：下一词预测、CJK 下一字/词/短语建议、有限上下文排序改进、
  专业语境识别、混合语言候选质量。不是聊天机器人，不是长文生成，不是云端写作助手。
- 原文提交与基础候选**永不等待**模型；统计候选先返回。
- 神经预测在后台有界执行；用户继续输入后旧版本预测必须取消或丢弃；
  超时静默回退基础候选；只更新仍属于当前 Session 与当前输入版本的候选。
- 敏感字段不向模型传递上下文。
- **不得**根据模型预测直接修改用户已上屏文本；不得默认自动接受预测。
- Windows **不得**把大型模型直接加载进所有宿主进程中的 TSF DLL；
  应研究独立本地预测服务与严格 IPC 协议。Android 应使用受控的应用私有运行环境
  与独立推理任务。

### 4.5 多学科领域体系

用户可选择 General / Computer Science / Biology / Medicine / Mathematics /
Physics / Chemistry / Engineering / Law / Economics / Finance / Literature /
History 等领域配置。领域名称是配置，不等于每个领域一套独立大模型。

**禁止**：

- 同时选择两个领域就下载两个完整模型；
- 同时运行两套完整模型再拼接候选；
- 在两套未校准的分数上机械求和；
- 领域数量增加导致完整模型内存线性增长。

优先架构：**单一共享多语言基础模型 + 统一领域路由 + 领域词汇索引 +
经校准的联合候选排序**。领域配置可以是轻量的术语词库、术语权重、领域特征、
轻量适配器与领域标签。只有离线评测证明收益显著且资源允许时，才考虑 LoRA 一类
参数高效适配，且适配器必须与共享基础模型的版本和 tokenizer 兼容。

跨学科（Biology+Computer Science → 生物信息学；Medicine+Chemistry → 药物化学）
必须作为联合语境处理，不得简化为两个候选列表。领域标签跨语言共享概念，
但表面词形、翻译与排序仍由各语言规则处理。

### 4.6 模型资源管理

- **模型元数据可以默认提供；模型权重不得默认下载。**
- 模型清单至少包含：`model_id`、`display_name`、`upstream_repository`、`revision`、
  `artifact_path`、`sha256`、`license`、`model_family`、`tokenizer_identity`、
  `quantization`、`supported_languages`、`supported_domains`、
  `runtime_compatibility`、`estimated_memory`、`estimated_storage`、
  `installation_state`。
- 禁止用不固定的 `latest` 作为可重复构建身份。
- 内测期使用官方 Hugging Face 或其他核实过的原始来源；用户主动请求下载；
  下载前显示文件大小、来源与许可；支持取消；校验 SHA-256；失败不得破坏已安装模型；
  不得静默下载其他模型；模型文件与个人学习数据分别存放；
  删除模型不得删除用户偏好，反之亦然。
- Windows：下载由用户明确启动的独立模型管理程序负责；
  TSF DLL、语言引擎与预测执行进程不得因此获得隐式联网能力。
- Android：优先浏览器下载 + 系统文件选择器导入，使输入法 APK 可继续不申请
  `INTERNET` 权限。**不得**声称同一 APK 中某个无网络 Activity 能独立撤销整个应用已声明的权限。

## 5. 隐私与离线要求

1. 运行期不联网：不发起任何网络请求，无遥测、无崩溃上报、无静默更新、无云候选。
2. 不上传输入内容：任何用户键入、组合中或已上屏文本均不得离开设备。
3. 不记录原始输入：诊断日志只允许记录不含用户内容的枚举值与计数；
   禁止把按键、preedit、commit 文本或其可逆编码写入日志、崩溃转储或错误报告。
4. 隐私字段不学习：密码字段、一次性验证码字段、以及被宿主或平台标记为敏感的字段，
   一律排除在学习与持久化之外。
5. 平台差异必须如实表述（**不得承诺不存在的 Windows 权限保证**）：
   - Windows：普通（非打包、非容器化）TSF DLL 被注入到任意宿主进程，
     OS **不会**给它一个"禁用网络"的权限位。此处的离线保证是**架构性与工程性**的
     （自有代码与依赖不含 socket 调用 + 代码审查 + 依赖策略），
     不是操作系统强制的。
     导入表/依赖列表一类检查只能覆盖**静态导入**，覆盖不到运行期动态加载，
     因此**禁止**把它表述为"离线安全已验证"（见威胁模型 3.8）。
   - Android：可通过在清单中**不申请** `android.permission.INTERNET` 获得平台级强制；
     该权限一经声明即不可按页面细粒度收回，因此默认不声明。
6. 不承诺"绝对安全"或"不可恢复删除"。删除语义只能承诺到"我们做了什么"的层级
   （见威胁模型第 6 节）。
7. 学习数据只在本机：偏好、计数与个人词条不得上传。必须提供"关闭学习"与"清除学习"，
   且两者都不影响正常打字。未分类字段按敏感处理。
8. 神经模型只按用户明确选择获取和启用：不做隐式下载、不做后台拉取、
   不把用户上下文发送给任何远端推理。模型权重与个人偏好分开存放、分开删除。
9. 敏感字段既不学习，也不向模型提供上下文；该判断必须在**写入侧**生效，
   不能靠读取侧过滤。

## 6. 验收原则

- **可执行即证据**：任何"通过"结论必须附带真实命令、真实退出码与真实测试数量；
  缺失工具时标记为部分验证并列出阻塞项，不得伪造成功。
- **测试必须能失败**：每条验收项都要存在一个在实现错误时会转红的用例；
  无条件成功的脚本不计入验收。
- **不越阶段**：每阶段只验收该阶段范围。P0.1 不以"能输入文字"作为验收条件——
  此时**不应**存在任何输入能力。
- **探针不冒充能力**：字节级 UTF-8 检查不等于 Unicode 合规测试，更不等于输入法能力测试；
  文档与报告必须按此措辞。
- **来源可核**：关于 librime / TSF / Android IME 行为的需求表述，需注明核对过的实际

- **许可证不由实现者决定**：保留负责人已选择的 AGPL-3.0-only 与许可决定记录；第三方资料另行核对，不把项目许可当作资料再分发授权。

## 7. 仍未实现的能力

本节只列**产品能力**缺口。工程进度以 `README.md` 的阶段状态表与
`docs/reports/` 的阶段报告为准；下面的表述若与二者不一致，以后者为准。

- 英文已有离线语料频率、上下文补全/下一词、形态、二编辑拼写、分段、显式和模型驱动缩写；这些算法与真实资源测试不等于完整产品验收。产品个人学习尚未获得可覆盖 worker 调用的字段权限锁；完整 Unicode 语言学、句首/标点和跨应用一致性仍未验收。
- Windows TSF 组件已存在（W1–W3-B）：产品 DLL 接到真实 key sink、上下文观察、协调器、
  UIElement 候选与 `DllRegisterServer`/`DllUnregisterServer`。当前源码对应的正式包尚无完整的
  真实宿主输入与安装/卸载验收；旧包的注册实验不等于该闭环已通过。
  公开发行逐项条件与证据格式见 `docs/product/release-gate.md`。
- 历史产品包包含 42,356 行英文词表，新增本地验证包具有五语言语料模型、词典和 profile 资源；两者不能混称为已验收的正式发行包。后端有有界 ID 计数学习存储，但产品路径未启用持久学习；公开数据分发、署名完整性与 relinkable 交付仍需独立验收。
- **语言身份层**（`engine/locale`）已实现 BCP 47 解析、lookup 匹配、七语言优先级与
  三级输入方案状态，并有 3 条 CTest。它**未**与 `tools/backend/stage_resources.py`
  的 13 个 profile 合并成单一数据源；两套清单分叉是已知风险。
- **自适应排序与学习事件语义**（`engine/ranking`）已实现并有 13 条 CTest，
  但**未接进** `epocanva_backend` 候选生成或 TSF 产品路径；学习模型只在内存，
  没有持久化、迁移或崩溃恢复。因此不能宣称产品已经会学习或会智能排序。
- Spanish、German 及其余声明语言：只有身份与优先级，**没有**引擎、词表或 profile 条目。
  中文的 `zh-Hant-TW`、`zh-Hant-HK`、`yue-Hant-HK` 与双拼/仓颉/五笔/粤拼同样只有身份。
- 无 Android IME 组件。
- 无模型目录、下载器、离线导入或安装状态机；无领域路由与领域词表。
  神经重排器有推理代码，但不接产品、默认不启用、无真实场景延迟数据。
- 无 CI 工作流；所有构建与测试结论都来自单机手工执行。
- 无签名、更新通道或可公开分发的安装包。
- 无 Rust 组件。
- 输入语言 profile 资源已与界面本地化分离；多语言输入不能由翻译界面文案代替。设置界面尚未完成系统性 i18n，本地 profile 包与受控测试也不能替代真实物理键盘/宿主验收。
