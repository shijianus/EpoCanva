## 3. 两项旧推论的纠正（任务书第二节要求的两条）

### 3.1 "没有 `boost_regex.lib`" 不是链接阻塞 —— 已推翻

P1.1 第 9 节把这条列为**阻塞 librime 链接的第 1 项**，并预备了一个
"给 `CMakeLists.txt:68` 补 `REQUIRED COMPONENTS regex`" 的补丁建议。本轮判定该推论**错误**，
且那个补丁**如果真打上反而会破坏构建**。六条证据：

1. 【源码】librime 用到的 Boost 组件里，7 个在 1.89.0 **没有任何编译源**：
   `libs/{unordered,signals2,uuid,interprocess,algorithm,crc,range}/src/*.cpp` 计数全为 **0**。
2. 【源码】`regex` 是唯二有编译源的，且 `libs/regex/src` 只有 `posix_api.cpp`、`wide_posix_api.cpp`，
   实现的是 **C POSIX 兼容层**（`regcomp`/`regexec`/`regwcomp`）。
   `libs/regex/build/Jamfile.v2:152-157` 的 `lib boost_regex : ../src/$(SOURCES)` 只编这两个，
   并且 `:162` 给使用者导出 `<define>BOOST_REGEX_NO_LIB=1`。
   `libs/regex/CMakeLists.txt:11` 更直接：`add_library(boost_regex INTERFACE)` —— CMake 侧**根本不产出 .lib**。
3. 【源码】librime 用的是 C++ 模板接口（5 个头包含 `<boost/regex.hpp>`：
   `src/rime/algo/calculus.h:12`、`algo/encoder.h:11`、`gear/recognizer.h:10`、`gear/speller.h:10`、
   `gear/translator_commons.h:10`），**从不包含** `boost/cregex.hpp`。
   触发 MSVC auto-link `#pragma comment(lib,…)` 的唯一位置是 `boost/regex/v5/cregex.hpp:29-30`，
   而 `boost/regex.hpp:28-31` 只包含 `regex/config.hpp` 与 `regex/v5/regex.hpp`，
   后者第 28–71 行的包含清单里**没有 `cregex.hpp`**（在整棵 `boost/regex/` 里 grep `cregex.hpp` 命中 0）。
   → 包含 `boost/regex.hpp` 不会产生任何库依赖。
4. 【源码】上游 Windows 自己的流程与此一致：`install-boost.bat:19-20` 只做
   `call .\bootstrap.bat` 然后 `.\b2 headers`，**不编译任何 Boost 库**；
   `.github/workflows/windows-build.yml:68-69` 在生产 `rime.dll` 的流水线上用的正是这一步。
5. 【实测】本轮用一个与 `third_party/librime/CMakeLists.txt:68` 完全相同的
   `find_package(Boost 1.77.0)`（配合 `Boost_USE_STATIC_LIBS=ON`、`Boost_USE_MULTITHREADED=ON`、
   `Boost_USE_STATIC_RUNTIME=ON`）指向解压后的 `boost_1_89_0` 树：

   ```
   -- Found Boost: …/boost_1_89_0 (found suitable version "1.89.0", minimum required is "1.77.0")
   -- Boost_FOUND        = TRUE
   -- Boost_LIBRARIES    =            ← 空
   -- Boost_LIBRARY_DIRS =            ← 空
   -- Boost_VERSION      = 108900
   ```

   随后把上述 8 个库的真实用法写成一个 x64 /MT 程序，**编译 + 链接 + 运行全部成功（退出码 0）**，
   `dumpbin /dependents` 只有 `KERNEL32.dll / USER32.dll / ADVAPI32.dll`。
6. 【实测】librime 本体在本次正式构建里同样在 `${Boost_LIBRARIES}` 为空的前提下
   编译并链接出了 `rime.dll`（见 §6）。`src/CMakeLists.txt:47` 的 `${Boost_LIBRARIES}` 展开为空
   是**正确结果**，不是缺陷。

文档已相应更新：`docs/compliance/dependency-audit.md` §5.4（新增）、§3 表第 9 行、§7 结论第 2 条；
`docs/build/librime-windows-baseline.md` §9.2 作废、§10 重写。

**顺带纠正的一个次要推论**：`find_package(Boost …)` 在 `cmake_minimum_required(3.12)`
（即 CMP0144 为 OLD）下会警告 `find_package is ignoring the variable` 关于 `BOOST_ROOT`，
但 FindBoost 模块本身仍读该缓存项，实测确实找到了。
本轮因此把 `BOOST_ROOT` 与 `Boost_INCLUDE_DIR` 都作为 **CMake 缓存变量**显式传入，
不依赖全局环境变量。

### 3.2 `/MT` 只是本轮实验选择 —— 已降级，并补上所有权规则

P1.1 的表述是"静态 CRT **避免**目标应用已加载另一种 VC 运行库这一类冲突，
也不需要随包分发 VCRedist；这是选 `/MT(d)` 的主要工程理由"。
本轮把它改成：

- `/MT` 是**本轮构建实验**的取值，理由只有一条可验证性：产物不依赖 VC 运行库 DLL，
  能用 `dumpbin /dependents` 直接判定开关是否真的生效。
- **不宣称它自动解决跨 DLL 运行库问题**。`/MT` 只统一了"堆与 CRT 对象在同一镜像里"，
  它完全不回答"谁分配、谁释放"。
- **发行策略未决定**。`/MT` 还是 `/MD`+VCRedist 要等 rime-adapter 与 TSF 宿主注入实验之后出 ADR。
  本轮的选择**不外推**为项目永久策略。

新增的 API 分配/释放/所有权规则表写在 `docs/build/librime-windows-baseline.md` §6.1，
来源是本轮读 `third_party/librime/src/rime_api_impl.h` 的实证（行号在文中）：

| 接口 | 分配 | 释放 | 客户端禁止 |
| --- | --- | --- | --- |
| `get_status` → `schema_id`、`schema_name` | rime.dll 内 `new char[n+1]`（`:347-350`） | `free_status` 内 `delete[]`（`:364-365`） | 自行 `free`/`delete[]`/改写 |
| `get_context` → `preedit`、`commit_text_preview`、`candidates[].text/comment`、`select_keys`、`select_labels[]` | rime.dll 内 `new char[]`（`:223`、`:231` 等） | `free_context` 内逐字段 `delete[]`（`:288-304`） | 同上 |
| `get_commit` → `text` | rime.dll 内 `new char[]`（`:319-320`） | `free_commit` 内 `delete[]`（`:330`） | 同上 |
| `get_input`、`get_version` | rime.dll 内部 | **无** free 接口 | 不得 free；只读；不得跨 `finalize()` 保存 |
| `get_*_dir_s(char*, size_t)` | **调用方**缓冲区 | 调用方 | `buffer_size` 单位 = **UTF-8 码元（字节）**；实现是 `strncpy`（`rime_api.cc:49-73`），**截断时不补 `\0`** |
| `RimeSessionId` | rime.dll 内 `Service` 持 `an<Session>` | `destroy_session` / `finalize`（`service.cc:80-83,120-126`） | 不得解引用；它只是 `reinterpret_cast<uintptr_t>`（`service.cc:92`） |

生命周期程序严格按此实现：**没有对任何上游对象调用 `delete`/`free`**，
每个成功的 `get_*` 都配对了 `free_*`。

## 5. 依赖构建的实际过程与两处真实障碍

### 5.1 目录布局（全部在被忽略的 `build/` 内）

### 5.2 障碍一：OpenCC 的 `install` 需要词典与工具（已查清，不是可选）

任务书要求"检查 OpenCC 词典生成是否为实际必需目标"。答案【源码 + 实测】：**是**，
且配置阶段就硬需要 Python：

- `deps/opencc/data/CMakeLists.txt:1` = `find_package(PythonInterp REQUIRED)`，
  而 `deps/opencc/CMakeLists.txt:225` 的 `add_subdirectory(data)` **无条件执行**，
  没有任何 option 能跳过 → 配置期就要解释器。
  【实测】`-- Found PythonInterp: C:/Python314/python.exe (found version "3.14.3")`。
- `data/CMakeLists.txt:39-44` = `add_custom_target(Dictionaries ALL DEPENDS …)` ——
  **带 `ALL`**，属于默认目标。
- `data/CMakeLists.txt:150-155` = `install(FILES ${DICT_GENERATED_DIR}/${DICT}.ocd2 …)` ——
  安装规则引用生成物；`src/tools/CMakeLists.txt:19-22` 又安装 `opencc.exe`、
  `opencc_dict.exe`、`opencc_phrase_extract.exe`。
  所以只 `--target libopencc` 再 `cmake --install` 会失败
  （【实测】`CMake Error at …/src/tools/cmake_install.cmake:37 (file): file INSTALL cannot find …`）。

处理方式：按上游默认目标构建（`ALL_BUILD`，含词典与三个工具）后 `cmake --install`，
词典由 OpenCC 自己树内的 `data/dictionary/*.txt` 加其 `data/scripts/{merge,reverse,common}.py`
在本机既有 Python 3.14.3 下生成。这三个脚本本轮**逐行读过**：
只做本地文本读写与排序（`codecs.open(..., encoding='utf-8')`、`sorted(dic.keys())`），
**无网络、无 subprocess、无 eval**。产物：`prefix/share/opencc/` 下 16 个 `.ocd2` + 14 个 `.json`。

未安装任何 Python：本机已有 `C:\Python314\python.exe`（3.14.3，PATH 第一命中）与
`C:\Programing\Python\Python3.11.9\python.exe`（3.11.9，本轮未用）。任务书"如构建必需 Python
且本机没有则停止"的分支**未触发**。

许可面（任务书 §6.8）：OpenCC 的 `README.md:242-244` 声明整个项目为 Apache License 2.0，
`LICENSE` 已在 lock 中按 556ed224 提交核验，该提交**无 `NOTICE` 文件**。
但 `data/dictionary/*.txt` 的**逐文件来源**上游没有记载 → 记为

### 5.3 障碍二：OpenCC 的外部 marisa（任务书 §6 的 1–4 条）

**核对结果：固定提交的 OpenCC 1.1.9 在 CMake 选项层面支持外部 marisa，但在 MSVC 上开箱不可用**，
缺两件上游只为**内置**那份 marisa 做的事：

| 事实 | 位置【源码】 |
| --- | --- |
| `option(USE_SYSTEM_MARISA …)` 存在 | `deps/opencc/CMakeLists.txt:35` |
| ON 分支只 `find_library(LIBMARISA NAMES marisa)`，**该变量之后再没被使用** | `:212-219` |
| 只有 **OFF** 分支才 `include_directories(../deps/marisa-0.2.6/include)` | `deps/opencc/src/CMakeLists.txt:6-8` |
| `target_link_libraries(libopencc marisa)` 用的是**裸名字**，OFF 分支下那是个真实 target | `src/CMakeLists.txt:118` |
| `install(TARGETS …)`：OFF 时装 `libopencc marisa`，ON 时只装 `libopencc` | `src/CMakeLists.txt:149-153` |

第二条独立障碍：**marisa 0.3.1 的公共头使用 C++17 设施**
（`std::string_view`、嵌套命名空间定义），而 OpenCC 只给 GNU/Clang 写 `-std=c++14`，
对 MSVC **不设置任何标准**（`deps/opencc/CMakeLists.txt:155-178`）。

**兼容性的真实编译证据**（两条都跑过）：

1. 只给包含目录、不提升标准 → 失败：
   ```
   …/prefix/include/marisa/key.h(22,21): error C2039: "string_view": 不是 "std" 的成员
   …/prefix/include/marisa/agent.h(12,11): error C2429: 语言功能"嵌套命名空间定义"需要编译器标志 "/std:c++17"
   ```
2. `-DCMAKE_CXX_STANDARD=17` + 补齐包含/链接目录 → **成功**：
   `libopencc` 全部 19 个 TU 编译通过，产出 `opencc.lib`，退出码 0。
   → **OpenCC 1.1.9 与固定的 marisa 0.3.1 在 API 上兼容，前提是 C++17。**

未打上游补丁的落地做法：CMake 官方文档化的
`CMAKE_PROJECT_<projectName>_INCLUDE` 钩子（本工程项目名为 `opencc`，
见 `deps/opencc/CMakeLists.txt:21-22`），指向自有文件
`tools/cmake/opencc_external_marisa_includes.cmake`，由它执行
`include_directories()` + `link_directories()`，并额外传 `-DCMAKE_CXX_STANDARD=17`。
钩子文件里还带 `FATAL_ERROR` 自检：`marisa.h` 或 `marisa.lib` 不在指定位就直接失败。

**试过并否定的两条路（写进文档防止重犯）：**

- `-DCMAKE_CXX_FLAGS:STRING=/I"<prefix>/include"` →
  CMake 的命令行解析**剥掉引号**，含空格路径被拆成
  `/ID:\Users\Smart` 与 ` Kevin\…` 两段，编译器在 try-compile 阶段就失败
  （【实测】`error C1083` + `CMake will not be able to correctly generate this project`）。
- 在会话里设 `INCLUDE` / `LIB` 环境变量 →
  CMake 生成的 `.vcxproj` 用 `AdditionalIncludeDirectories`，
  **不读** `$(INCLUDE)`，实测 `MarisaDict.cpp(23,10): error C1083: 无法打开包括文件 "marisa.h"`。

**"同一进程两份 marisa" 的共存风险：本轮直接消除，且有实测证据。**
`USE_SYSTEM_MARISA=ON` 生效时【实测】：

```
-- EpoCanva external-marisa hook: includes …/prefix/include; link dirs …/prefix/lib
-- libmarisa found: …/prefix/lib/marisa.lib
  opencc linked marisa : …/prefix/lib/marisa.lib
  opencc bundled marisa-0.2.6 : not configured, not built, not referenced in the build log
  prefix/lib marisa copies : marisa.lib          （仅此一个）
```

OpenCC 的整棵构建树里没有 `marisa.vcxproj`，其构建日志里 `marisa-0.2.6` 出现 **0 次**。
所以 `rime.dll` 里只有 marisa **0.3.1 一个实现**，不存在"OpenCC 用 0.2.6 头编译却链到 0.3.1 实现"
这种静默混用。脚本对这一点设有断言，任何偏差直接失败。

**最小上游补丁建议（本轮未应用，仅登记）**，写在
`docs/build/librime-windows-baseline.md` §10.1：反转 `src/CMakeLists.txt:6-8` 的条件、
把 `:118` 改成 `target_link_libraries(libopencc ${LIBMARISA})`、
在根 `CMakeLists.txt` 为 MSVC 设 `CMAKE_CXX_STANDARD 17`。

**这是一个"没有任何可用组件的空引擎"** —— 生命周期成立，但**完全没有输入能力**。

### 8.2 DLL 放置与查找：显式、受控，且有身份校验

- 构建侧：`add_custom_command(TARGET … POST_BUILD copy_if_different <install>/lib/rime.dll → $<TARGET_FILE_DIR>/rime.dll)`，
  放在 exe 同目录（Windows 默认搜索顺序第一项），**不依赖 PATH**。
- 查找侧：`find_file/find_library` 全部带 `NO_DEFAULT_PATH`，只在给定前缀内解析，
  解析结果再用 `string(FIND …)` 强制断言必须以该前缀开头 → 机器上别处的 librime 无法混入。
- 运行侧：程序用 `GetModuleHandleExW(FROM_ADDRESS, (LPCWSTR)api->get_version, &hmod)`
  反查"到底哪个模块提供了这段代码"，`GetModuleFileNameW` 取路径，与 `--expect-dll` 归一化后比较。
- 【实测】`dumpbin /dependents` 只列出 `rime.dll` + `KERNEL32.dll`；
  exe 的 `main.obj` 带 `/FAILIFMISMATCH:RuntimeLibrary=MT_StaticRelease`（与 `rime.lib` 同种 CRT）；
  exe 本身是 `8664 machine (x64)`；
  放置的 `rime.dll` 与安装目录里的**SHA-256 完全相同**
  （`333b5fa0…d7609e9a`），证明不是旧 DLL。

function Invoke-BaselineStep {
    <#
      Runs one native command, appends combined output to a numbered log file,
      and returns stdout lines. Throws with the stage name on a non-zero exit code
      or on a missing executable.
    #>
    [CmdletBinding()]
    param(
        [Parameter(Mandatory)][string]$Stage,
        [Parameter(Mandatory)][string]$Exe,
        [Parameter()][string[]]$Arguments = @()
    )

    $resolved = Get-Command $Exe -ErrorAction SilentlyContinue
    if (-not $resolved) {
        throw "stage '$Stage': executable not found: $Exe"
    }
    # Get-Item on a bare name like 'dumpbin.exe' resolves against the current
    # directory, not PATH, so the command lookup result is what gives the full path.
    $display = $resolved.Source

    $script:StepIndex++
    $logName = '{0:D2}-{1}.log' -f $script:StepIndex, ($Stage -replace '[^A-Za-z0-9_.-]', '_')
    $logPath = Join-Path $script:LogDir $logName
    # The format operator must be inside parentheses here: in argument position a
    # bare `-f` is parsed as a parameter name of Write-Host (-ForegroundColor).
    Write-Host ("[step {0:D2}] {1}" -f $script:StepIndex, $Stage)
    Write-Host "        exe : $display"
    foreach ($a in $Arguments) { Write-Host "        arg : $a" }

    # Native tools write progress and warnings on stderr. Under
    # $ErrorActionPreference='Stop' PowerShell turns those into terminating errors
    # (NativeCommandError), which would mask real exit codes, so the preference is
    # relaxed only for the duration of the call.
    $previousPreference = $ErrorActionPreference
    $ErrorActionPreference = 'Continue'
    try {
        # & with an array never re-parses the arguments; PowerShell quotes each element.
        $out = & $display @Arguments 2>&1 | ForEach-Object { $_.ToString() }
        $code = $LASTEXITCODE
    } finally {
        $ErrorActionPreference = $previousPreference
    }

    $header = @(
        "stage       : $Stage"
        "executable  : $display"
        "arguments   :"
    ) + ($Arguments | ForEach-Object { "  |$_" }) + @("exit code   : $code", '')
    ($header + $out) | Set-Content -Path $logPath -Encoding UTF8

    if ($code -ne 0) {
        Write-Host "---- last 40 lines of $logName ----" -ForegroundColor Red
        $out | Select-Object -Last 40 | ForEach-Object { Write-Host $_ }
        throw "stage '$Stage' failed with exit code $code (log: $logName)"
    }
    return $out
}

function Get-CacheEntry {
    param([Parameter(Mandatory)][string]$BuildDir,
          [Parameter(Mandatory)][string]$Key)
    $cache = Join-Path $BuildDir 'CMakeCache.txt'
    Test-PathOrThrow $cache "CMake cache under $BuildDir"
    $line = @(Get-Content -LiteralPath $cache |
        Where-Object { $_ -match "^$([regex]::Escape($Key)):" } |
        Select-Object -First 1)
    if ($line.Count -eq 0) { return $null }
    return ($line[0] -split '=', 2)[1]
}

# A successful configure does not prove the intended option took effect: a typo in
# an option name is silently ignored by CMake. Each dependency therefore re-reads
# its own cache and fails the stage when a value differs from what was requested.
function Assert-CacheValue {
    param([Parameter(Mandatory)][string]$BuildDir,
          [Parameter(Mandatory)][hashtable]$Expect,
          [Parameter(Mandatory)][string]$Stage)
    foreach ($key in ($Expect.Keys | Sort-Object)) {
        $want = $Expect[$key].Replace('\', '/')
        $got = Get-CacheEntry -BuildDir $BuildDir -Key $key
        if ($null -eq $got) {
            throw "${Stage}: cache entry '$key' is absent -- the option name is not defined by this project"
        }
        if ($got.Replace('\', '/') -ne $want) {
            throw "${Stage}: cache entry '$key' = '$got', requested '$want'"
        }
        Write-Host "  cache ok : $key = $got"
    }
}

# Where a library actually came from, rather than merely that something was found.
function Assert-CacheUnder {
    param([Parameter(Mandatory)][string]$BuildDir,
          [Parameter(Mandatory)][string[]]$Keys,
          [Parameter(Mandatory)][string]$Root,
          [Parameter(Mandatory)][string]$Stage)
    $rootNorm = $Root.Replace('\', '/').TrimEnd('/').ToLowerInvariant()
    foreach ($key in $Keys) {
        $got = Get-CacheEntry -BuildDir $BuildDir -Key $key
        if ([string]::IsNullOrWhiteSpace($got)) {
            throw "${Stage}: '$key' resolved to nothing; the dependency was not located"
        }
        if ($got.Replace('\', '/').ToLowerInvariant().StartsWith($rootNorm) -eq $false) {
            throw "${Stage}: '$key' points outside the intended root ($Root): $got"
        }
        Write-Host "  provenance ok : $key = $got"
    }
}

# CMake ignores most -D values when a cache already exists, and
# CMAKE_USER_MAKE_RULES_OVERRIDE is read only by the very first configure of a
# build directory. Reusing a directory built with different flags therefore
# silently produces a different CRT than requested, so it is refused instead.
function Assert-NoStaleCache {
    param([Parameter(Mandatory)][string]$BuildDir,
          [Parameter(Mandatory)][string]$Stage)
    $cache = Join-Path $BuildDir 'CMakeCache.txt'
    if (-not (Test-Path -LiteralPath $cache)) { return }
    $gen = Get-CacheEntry -BuildDir $BuildDir -Key 'CMAKE_GENERATOR'
    $cfgTypes = Get-CacheEntry -BuildDir $BuildDir -Key 'CMAKE_CONFIGURATION_TYPES'
    $cxxRelease = Get-CacheEntry -BuildDir $BuildDir -Key 'CMAKE_CXX_FLAGS_RELEASE'
    if ($gen -and $gen -ne $Generator) {
        throw "${Stage}: $BuildDir was configured with generator '$gen', not '$Generator'. Rerun with -Fresh."
    }
    if ($cfgTypes -and $cfgTypes -ne 'Release') {
        throw "${Stage}: $BuildDir was configured with CMAKE_CONFIGURATION_TYPES='$cfgTypes'. Rerun with -Fresh."
    }
    if ($cxxRelease -and $cxxRelease -notmatch '/MT') {
        throw "${Stage}: $BuildDir already has CMAKE_CXX_FLAGS_RELEASE='$cxxRelease', which is not the static CRT. The make-rules override only applies to a fresh build directory. Rerun with -Fresh."
    }
    Write-Host "  reusing an existing cache that already matches this configuration"
}

function New-Dependency {
    param(
        [Parameter(Mandatory)][string]$Name,
        [Parameter(Mandatory)][string]$SourceDir,
        [Parameter(Mandatory)][string[]]$ExtraArgs,
        [hashtable]$Expect = @{}
    )
    $bin = Join-Path $DepBuild $Name
    if (-not (Test-Path -LiteralPath $bin)) { New-Item -ItemType Directory -Path $bin | Out-Null }
    Assert-NoStaleCache -BuildDir $bin -Stage $Name

    Write-Head "dependency: $Name"
    $cfg = @('-S', $SourceDir, '-B', $bin) + $CommonArgs + $ExtraArgs
    Invoke-BaselineStep "$Name.configure" $CMake $cfg | Out-Null
    $Expect['CMAKE_INSTALL_PREFIX'] = $Prefix
    $Expect['CMAKE_CONFIGURATION_TYPES'] = 'Release'
    Assert-CacheValue -BuildDir $bin -Expect $Expect -Stage $Name
    Invoke-BaselineStep "$Name.build" $CMake (@('--build', $bin) + $BuildArgs) | Out-Null
    Invoke-BaselineStep "$Name.install" $CMake (@('--install', $bin, '--config', 'Release')) | Out-Null
    return $bin
}

// Finds the module that actually supplies the code behind an API function

std::wstring LoadedModulePath(const void* address) {
  HMODULE module = nullptr;
  if (!GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS |
                              GET_MODULE_HANDLE_EX_FLAG_UNCHANGED_REFCOUNT,
                          reinterpret_cast<LPCWSTR>(address), &module) ||
      !module) {
    return std::wstring();
  }
  std::vector<wchar_t> buffer(kPathBuffer, L'\0');
  const DWORD n = GetModuleFileNameW(module, buffer.data(),
                                     static_cast<DWORD>(buffer.size()));
  if (n == 0 || n >= buffer.size()) {
    return std::wstring();
  }
  return NormalizeWide(std::wstring(buffer.data(), n));
}

int CountFilesBeneath(const std::filesystem::path& dir) {
  std::error_code ec;
  if (!std::filesystem::exists(dir, ec) || ec) {
    return 0;
  }
  std::error_code bec;
  std::filesystem::recursive_directory_iterator it(
      dir, std::filesystem::directory_options::skip_permission_denied, bec);
  if (bec) {
    return -1;
  }
  int count = 0;
  const std::filesystem::recursive_directory_iterator end;
  for (; it != end; it.increment(ec)) {
    if (ec) {
      break;
    }
    std::error_code fec;
    if (it->is_regular_file(fec) && !fec) {
      ++count;
    }
  }
  return count;
}

  if (!api->get_version) {
    Fail(kLoadedModuleMismatch, "module.identity", "get_version slot is NULL");
    return kLoadedModuleMismatch;
  }
  const std::wstring actual =
      LoadedModulePath(reinterpret_cast<const void*>(api->get_version));
  if (actual.empty()) {
    Fail(kLoadedModuleMismatch, "module.identity",
         "cannot resolve the module owning rime_get_api()");
    return kLoadedModuleMismatch;
  }
  if (_wcsicmp(actual.c_str(), opt.expect_dll.c_str()) != 0) {
    std::printf("[lifecycle] FAIL module.identity\n");
    std::printf("  expected: %ls\n  actual  : %ls\n", opt.expect_dll.c_str(),
                actual.c_str());
    Fail(kLoadedModuleMismatch, "module.identity",
         "loaded module is not the artefact this program was built against");
    return kLoadedModuleMismatch;
  }
  std::printf("[lifecycle] module-loaded    %ls\n", actual.c_str());
  std::printf("[lifecycle] librime-version  %s\n", api->get_version());
  return kOk;
}

ExitCode VerifyTraitsApplied(RimeApi* api, const Options& opt) {
  if (!RIME_API_AVAILABLE(api, get_shared_data_dir_s) ||
      !RIME_API_AVAILABLE(api, get_user_data_dir_s)) {
    Fail(kTraitsNotApplied, "traits.readback",
         "the loaded API table has no *_dir_s accessors");
    return kTraitsNotApplied;
  }
  // buffer_size counts bytes and the implementation strncpy()s, which does not
  // guarantee termination when it truncates; a full buffer is treated as failure.
  std::vector<char> buffer(kPathBuffer, '\0');
  api->get_shared_data_dir_s(buffer.data(), buffer.size());
  if (strnlen(buffer.data(), buffer.size()) >= buffer.size() - 1 ||
      strcmp(buffer.data(), opt.shared_dir.string().c_str()) != 0) {
    std::printf("  expected: %s\n  actual  : %s\n",
                opt.shared_dir.string().c_str(), buffer.data());
    Fail(kTraitsNotApplied, "traits.readback",
         "shared_data_dir did not take effect");
    return kTraitsNotApplied;
  }
  buffer.assign(kPathBuffer, '\0');
  api->get_user_data_dir_s(buffer.data(), buffer.size());
  if (strnlen(buffer.data(), buffer.size()) >= buffer.size() - 1 ||
      strcmp(buffer.data(), opt.user_dir.string().c_str()) != 0) {
    std::printf("  expected: %s\n  actual  : %s\n",
                opt.user_dir.string().c_str(), buffer.data());
    Fail(kTraitsNotApplied, "traits.readback", "user_data_dir did not take effect");
    return kTraitsNotApplied;
  }
  Log("traits.readback", "shared and user data dirs match what was set");
  return kOk;
}

// Steps 5 to 7 of the brief. *created_out keeps the id that was handed out even
// after it has been released, so the caller can assert post-finalize that it is
// gone; *still_alive reports whether the caller still has to destroy it.
ExitCode VerifySession(RimeApi* api, RimeSessionId* created_out, bool* still_alive) {
  const RimeSessionId created = api->create_session();
  if (created == kNoSession) {
    std::printf("[lifecycle] FAIL session.create\n");
    std::printf("  create_session() returned the invalid id while shared_data_dir "
                "was empty; the minimal configuration a session actually needs is "
                "a deployable default.yaml plus the schema/dictionary it names "
                "(stage code %d)\n",
                static_cast<int>(kCreateSessionFailed));
    *created_out = kNoSession;
    *still_alive = false;
    return kCreateSessionFailed;
  }
  *created_out = created;
  *still_alive = true;
  std::printf("[lifecycle] session.create     id=%llu\n",
              static_cast<unsigned long long>(created));

  if (!api->find_session(created)) {
    Fail(kFindSessionFailed, "session.find",
         "find_session() rejected the id create_session() just returned");
    return kFindSessionFailed;
  }
  Log("session.find", "find_session() returned True");

  {
    RIME_STRUCT(RimeStatus, status);
    if (!api->get_status(created, &status)) {
      Fail(kGetStatusFailed, "session.status", "get_status() returned False");
      return kGetStatusFailed;
    }
    std::printf("[lifecycle] session.status     schema_id=%s disabled=%d "
                "composing=%d\n",
                status.schema_id ? status.schema_id : "(null)",
                status.is_disabled, status.is_composing);
    const bool has_id = (status.schema_id && status.schema_id[0]);
    const bool enabled = (status.is_disabled == False);
    api->free_status(&status);
    if (!has_id) {
      Fail(kGetStatusFailed, "session.status",
           "a live session reported an empty schema_id");
      return kGetStatusFailed;
    }
    if (!enabled) {
      Fail(kGetStatusFailed, "session.status",
           "the service reports itself disabled right after initialize()");
      return kGetStatusFailed;
    }
    Log("session.status", "free_status() returned True");
  }

  {
    RIME_STRUCT(RimeContext, context);
    if (!api->get_context(created, &context)) {
      Fail(kGetContextFailed, "session.context", "get_context() returned False");
      return kGetContextFailed;
    }
    const bool has_preedit = (context.composition.preedit != nullptr);
    const int candidates = context.menu.num_candidates;
    api->free_context(&context);
    std::printf("[lifecycle] session.context    preedit=%s num_candidates=%d\n",
                has_preedit ? "present" : "none", candidates);
    // A session that was never given a key must have nothing composed and no
    // menu. Any text or candidate here would mean the reported state is invented.
    if (has_preedit || candidates != 0) {
      Fail(kGetContextFailed, "session.context",
           "a brand new session reported text or candidates without any input");
      return kGetContextFailed;
    }
    Log("session.context", "free_context() returned True");
  }

  {
    RIME_STRUCT(RimeCommit, commit);
    if (api->get_commit(created, &commit)) {
      const bool had_text = (commit.text != nullptr);
      api->free_commit(&commit);
      std::printf("[lifecycle] FAIL session.commit: get_commit() returned %s "
                  "although no key was ever sent\n",
                  had_text ? "text" : "True with a null text pointer");
      return kCommitQueueNotEmpty;
    }
    Log("session.commit", "get_commit() returned False, as expected");
  }

  if (!api->destroy_session(created)) {
    Fail(kDestroySessionFailed, "session.destroy",
         "destroy_session() returned False");
    // Leave still_alive set: the id may or may not be gone, and the caller's
    // cleanup path reports what it finds instead of assuming success.
    return kDestroySessionFailed;
  }
  if (api->find_session(created)) {
    Fail(kDestroySessionFailed, "session.destroy",
         "the destroyed id is still resolvable");
    *still_alive = false;
    return kDestroySessionFailed;
  }
  *still_alive = false;
  Log("session.destroyed",
      "destroy_session() True and the id no longer resolves");
  return kOk;
}

ExitCode VerifyAfterFinalize(RimeApi* api, RimeSessionId previously_created) {
  if (previously_created != kNoSession &&
      api->find_session(previously_created)) {
    Fail(kSessionAliveAfterFinalize, "post.finalize",
         "an id created before finalize() is still resolvable");
    return kSessionAliveAfterFinalize;
  }
  const RimeSessionId late = api->create_session();
  if (late != kNoSession) {
    api->destroy_session(late);
    Fail(kEngineRestartedAfterFinalize, "post.finalize",
         "create_session() still succeeds after finalize()");
    return kEngineRestartedAfterFinalize;
  }
  Log("post.finalize", "create_session() refused; the service is down");
  return kOk;
}

ExitCode VerifyNoLogFiles(const Options& opt) {
  const int files = CountFilesBeneath(opt.log_dir);
  // Built with ENABLE_LOGGING=OFF, so the body of SetupLogging() is compiled
  // away (third_party/librime/src/rime/setup.cc:71-95). Nothing may land here.
  if (files != 0) {
    std::printf("[lifecycle] FAIL post.finalize.log: %d file(s) written under "
                "the log directory\n",
                files);
    return kLogFilesWritten;
  }
  Log("post.finalize", "log directory stayed empty");
  return kOk;
}

}  // namespace

int main(int argc, char** argv) {
  Options opt;
  std::string error;
  if (!ParseArgs(argc, argv, &opt, &error)) {
    std::printf("usage: rime_lifecycle_smoke --expect-dll <path> "
                "--shared-dir <path> --user-dir <path> --log-dir <path>\n");
    std::printf("[lifecycle] FAIL arguments: %s\n", error.c_str());
    return kUsage;
  }

  for (const std::filesystem::path& d :
       {opt.shared_dir, opt.user_dir, opt.log_dir}) {
    std::error_code ec;
    std::filesystem::create_directories(d, ec);
    if (ec) {
      std::printf("[lifecycle] FAIL test.directories: cannot create %s (%s)\n",
                  d.string().c_str(), ec.message().c_str());
      return kTestDirectorySetupFailed;
    }
  }

  // --- 1. acquire the API table -------------------------------------------------
  RimeApi* api = rime_get_api();
  if (!api) {
    Fail(kApiUnavailable, "api.acquire", "rime_get_api() returned NULL");
    return kApiUnavailable;
  }
  Log("api.acquire", "rime_get_api() returned a table");

  // --- 2. prove which binary supplied that table --------------------------------
  ExitCode rc = VerifyModuleIdentity(opt, api);
  if (rc != kOk) {
    return rc;
  }

  // --- 3. traits, all paths project-local --------------------------------------
  // RimeTraits holds borrowed const char*, so the strings it points at must
  // outlive setup() and initialize(); they are named locals rather than
  // temporaries of the assignment statements.
  const std::string shared_s = opt.shared_dir.string();  // UTF-8 bytes / ANSI bytes
  const std::string user_s = opt.user_dir.string();
  const std::string log_s = opt.log_dir.string();

  RIME_STRUCT(RimeTraits, traits);
  traits.shared_data_dir = shared_s.c_str();
  traits.user_data_dir = user_s.c_str();
  traits.log_dir = log_s.c_str();
  traits.prebuilt_data_dir = nullptr;  // librime defaults to <shared>/build
  traits.staging_dir = nullptr;        // librime defaults to <user>/build
  traits.app_name = "rime.epocanva.lifecycle_smoke";
  traits.distribution_name = "EpoCanva";
  traits.distribution_code_name = "epocanva";
  traits.distribution_version = "0.0.0-p1.2";
  traits.min_log_level = 3;            // FATAL; inert while logging is OFF
  traits.modules = nullptr;            // librime's own default module group

  // --- 4. setup + initialize ----------------------------------------------------
  // initialize() is void, so it cannot report failure across the C boundary. What
  // it does leave behind is observable: the traits readback below shows the
  // deployer really took the settings, and create_session() shows the service came
  // up. Cleanup is driven by those observations, never by an assumed happy path.
  bool initialize_called = false;
  api->setup(&traits);
  Log("engine.setup", "setup() returned");
  api->initialize(&traits);
  initialize_called = true;
  Log("engine.initialize", "initialize() returned");

  rc = VerifyTraitsApplied(api, opt);
  RimeSessionId created = kNoSession;
  bool session_alive = false;
  if (rc == kOk) {
    // --- 5..7 session lifecycle -------------------------------------------------
    rc = VerifySession(api, &created, &session_alive);
  }

  // --- 8. finalize exactly what was brought up ---------------------------------
  if (session_alive) {
    if (api->destroy_session(created)) {
      Log("cleanup.session", "destroyed on the failure path");
    } else {
      std::printf("[lifecycle] cleanup.session destroy_session() also failed\n");
    }
    session_alive = false;
  }
  if (initialize_called) {
    api->finalize();
    Log("cleanup.finalize", "finalize() returned");
    const ExitCode post = VerifyAfterFinalize(api, created);
    if (rc == kOk && post != kOk) {
      rc = post;
    }
  } else if (rc == kOk) {
    rc = kApiUnavailable;
    std::printf("[lifecycle] FAIL cleanup: initialize() was never called\n");
  }

  const ExitCode logs = VerifyNoLogFiles(opt);
  if (rc == kOk && logs != kOk) {
    rc = logs;
  }

  if (rc == kOk) {
    Log("RESULT", "PASS full lifecycle");
  }
  return rc;
}
