## 2. 测试方案的组件与选择理由

**结论：不需要自定义组件即可满足任务书第五/六节的全部要求**，
因此不存在需要上报的实现缺口；下列 5 个组件的名字全部读自固定提交的注册调用
`third_party/librime/src/rime/gear/gears_module.cc:46-88`，**没有一个是猜出来的配置名**。

| 角色 | 组件（注册名） | 选择理由 / 被否定的替代 | 【源码】 |
| --- | --- | --- | --- |
| 小写 ASCII 字母入组合 | `speller`（processor） | 唯一承认键集合可配置的处理器：`speller/alphabet`。`fluid_editor` 单独使用会把 `0x21..0x7e` **任意**字节推进输入缓冲，那样"只有 a–z 会组合"根本不可断言 | `speller.cc:100-146`，默认字母表 `:20` |
| 退格 / 取消 / 提交 | `fluid_editor`（processor） | 其硬编码键表正是所需四操作；`_auto_commit=false`，确认候选不会顺手提交。`express_editor` **被否定**：`char_handler_ = DirectCommit` 且 auto_commit=true，第一个字母就会把组合冲掉 | `editor.cc:189-203`（fluid）、`:205-218`（express）、`:41-44` |
| 把字母串切成一段 | `abc_segmentor`（segmentor） | 读同一份 `speller/alphabet`，产 `"abc"` tag 段。`matcher` 需要 `recognizer/patterns`、`punct_segmentor` 需要标点表，都会把无关配置拖进夹具 | `abc_segmentor.cc:39-69` |
| 兜住未被覆盖的位置 | `fallback_segmentor`（segmentor） | 逐字符认领为 `"raw"` 段，使"没有位置处于未翻译状态"成为结构保证而非巧合 | `fallback_segmentor.cc:16-57` |
| 候选来源（关键一项） | `echo_translator`（translator） | 把该段自身的输入文本原样做成 `SimpleCandidate("raw", …)`，quality −100，**不打开词典、不读用户词典、不碰任何文件**。这就是"无词库"能成立的唯一原因。`script_translator`/`table_translator` 需要 `dictionary:`，`punct_translator` 需要标点表，`history_translator` 读提交历史 | `echo_translator.cc:30-43` |
| 无 filter | 省略 `engine/filters` | `CreateComponentsFromList` 取不到列表就什么都不做，少一个未知行为 | `engine.cc:298-326` |

配套的两处**关闭**动作（不是新增能力，而是削减组件默认行为）：

* `editor/char_handler: noop` → 把 `FluidEditor` 构造函数硬编码的 `AddToInput` 清成 `nullptr`，
  于是数字、大写字母、标点**不被夹具消费**。
  `editor.cc:34-39` 的表里 `"noop"` 对应 `nullptr`，`:74-85` 完成赋值。
* `editor/bindings: {space: noop}` → 抹掉构造函数绑的 `{XK_space,0} → Confirm`。
  `key_binding_processor_impl.h:71-78`：`Bind` 收到空 action 就 `erase`。
  于是本夹具**只有 Return 一个提交键**，"明确的提交操作"不歧义。

另外两条读源码后确认的"没有隐患"依据：

* `Switcher` 被作为 `processors_[0]` 无条件插入（`engine.cc:336-337`），
  但夹具没有 `switcher/hotkeys`，`hotkeys_` 保持空表且 `active_` 为 false
  → 对任何键都返回 `kNoop`（`switcher.cc:51-81`）。
* `shape_processor` 作为 post-processor 被无条件创建（`engine.cc:359-373`），
  但 `full_shape` 选项未开时立刻 `return kNoop`（`shape.cc:38-42`）。
  **这条很关键**：若 `full_shape` 被打开，post-processor 会把未处理的 ASCII 字符
  转成全角字符**直接提交**（`shape.cc:51-54`）——那将是"假提交"的来源，
  所以夹具必须不开任何 switch。

# EpoCanva P1.3 test fixture -- default settings for the raw input-link probe.

### 3.2 `tests/fixtures/rime_raw/epocanva_test_raw.schema.yaml`

```yaml
# EpoCanva P1.3 test fixture -- raw input-link probe schema.
#
# schema_id: epocanva_test_raw
#
# WHAT THIS IS: the smallest schema that lets a headless program prove that keys
# really travel  process_key -> processor -> segmentor -> translator -> context
# -> preedit/candidates, and that a composition really travels
# -> commit -> session commit queue -> get_commit.
#
# WHAT THIS IS NOT: it is not an English predictor, not an English completer,
# not a word list, not a spelling corrector and not a "minimal English MVP".
# It transliterates nothing: the candidate text is byte-identical to the keys the
# test injected. Passing every assertion in tools/rime_input_replay says only
# that the input link works for the seven ASCII keys the fixture claims to own.
#
# Every component name below was read out of the pinned checkout (librime 1.17.0,
# commit 33e78140250125871856cdc5b42ddc6a5fcd3cd4), from the Registry::Register
# calls in src/rime/gear/gears_module.cc:46-88. Nothing here is a guess and
# nothing here names a plugin, an external dictionary or a language model.

schema:
  schema_id: epocanva_test_raw
  # ASCII-only name on purpose: schema_name crosses the C ABI as UTF-8 bytes and
  # the replay program asserts on it byte-for-byte.
  name: EpoCanva raw link fixture
  version: "0.0.0-p1.3-fixture"

# No `switches:` section -> ConcreteEngine::InitializeOptions() finds nothing to
# reset (src/rime/engine.cc:376-395), so every RimeStatus flag the replay reads
# stays in its documented false state instead of depending on fixture ordering.

# Declared explicitly rather than inherited from default:/menu via
# DefaultConfigPlugin (src/rime/config/default_config_plugin.cc:22-28). Where the
# two differ the schema wins: IncludeReference::Resolve replaces the target with
# the included map and then merges the schema's own keys back over it
# (src/rime/config/config_compiler.cc:62-76).
menu:
  page_size: 5

engine:
  processors:
    # Owns exactly the lowercase ASCII letters listed in speller/alphabet.
    # A letter -> PushInput + BeginEditing -> kAccepted (src/rime/gear/speller.cc:128-145).
    # Anything else -> kNoop at :109-110, before any input is touched.
    - speller
    # Supplies the BackSpace / Escape / Return bindings. Its catch-all
    # "printable char goes into the input buffer" handler is switched off below,
    # which is what keeps this fixture from accepting digits and punctuation.
    - fluid_editor
  segmentors:
    # Groups a run of alphabet characters into one "abc"-tagged segment
    # (src/rime/gear/abc_segmentor.cc:39-69). Reads speller/alphabet, same key.
    - abc_segmentor
    # Claims any input position abc_segmentor left uncovered, one character at a
    # time, as a "raw" segment (src/rime/gear/fallback_segmentor.cc:16-57). With
    # an alphabet-gated speller nothing should ever reach it; it is present so
    # that "no position is left untranslated" is structurally guaranteed rather
    # than merely observed.
    - fallback_segmentor
  translators:
    # The only translation source: it turns the segment's own input text into a
    # single SimpleCandidate of type "raw" at quality -100
    # (src/rime/gear/echo_translator.cc:30-43). It opens no dictionary, no user
    # dictionary, no prediction model and no file handle.
    - echo_translator

speller:
  # Lowercase ASCII only, a-z. Deliberately not upstream's reverse-order default
  # "zyxwvutsrqponmlkjihgfedcba" (src/rime/gear/speller.cc:20) so that the fixture
  # states its own accepted key set.
  alphabet: "abcdefghijklmnopqrstuvwxyz"
  # No delimiter -> "'" and " " never enter the input buffer. With delimiter empty,
  # Speller::ProcessKeyEvent's `belongs_to(ch, delimiters_)` is false for every
  # character (std::string::find on an empty string returns npos).
  delimiter: ""
  # Left unset on purpose so initials_ == alphabet_ (src/rime/gear/speller.cc:95-97):
  # every letter is an initial, and no letter is ever rejected as "not a valid
  # spelling start". Also unset: auto_select, max_code_length, auto_clear,
  # use_space -> every one of those features keeps its source default
  # (auto_select_ false, max_code_length_ 0, auto_clear_ kClearNone, use_space_
  # false; src/rime/gear/speller.h:44-48) and no key can silently commit, clear or
  # auto-select anything behind the test's back.

editor:
  # fluid_editor's constructor hardcodes char_handler_ = &Editor::AddToInput
  # (src/rime/gear/editor.cc:201), which pushes ANY byte in 0x21..0x7e into the
  # input buffer (src/rime/gear/editor.cc:58-63). Selecting "noop" maps to the
  # nullptr entry of editor_char_handler_definitions
  # (src/rime/gear/editor.cc:34-39, 74-85) and clears it, so digits, uppercase
  # letters and punctuation are NOT consumed by this fixture.
  char_handler: noop
  # Unbinds the constructor's {XK_space, 0} -> Confirm binding
  # (src/rime/gear/editor.cc:191). A `noop` action erases the keymap entry
  # (Keymap::Bind, src/rime/gear/key_binding_processor_impl.h:71-78). Space is
  # therefore expected to be reported as unhandled, leaving exactly one commit
  # key in this fixture: Return.
  bindings:
    space: noop
```

任务书第六节"必须禁止"六条的实现方式：

| 禁止项 | 实现与证据 |
| --- | --- |
| 宿主回退模拟冒充引擎处理 | 程序只有 `process_key` 一个输入入口，无键盘钩子、无剪贴板、无宿主文本访问；未消费就记 `handled=0`（【实测】事件 1–3、12–14 全为 0） |

| API 失败后用空值继续 | `ReadObservedState` 任一 `get_*` 失败即返回 false，调用方 `return failure`（阶段码 11/12/13），并打印 "continuing with empty values is refused" |

| 未释放 API 结果 | `ApiBalance` 三对计数；`get_input` 无 free 接口 → 立即复制且从不释放。【实测】矩阵运行 `status 23/23 context 23/23 commit 1/1 -- paired` |

沿用已验证配置的方式：独立顶层工程（`if(NOT CMAKE_SOURCE_DIR STREQUAL …) FATAL_ERROR`）、
`CMAKE_MSVC_RUNTIME_LIBRARY "MultiThreaded"`、Release/x64/VS2022、
`find_file/find_library` 全带 `NO_DEFAULT_PATH` 并再断言解析结果必须落在给定前缀内、
POST_BUILD 把 `rime.dll` 复制到 exe 同目录。**原有生命周期工程的 CRT 未改。**

关于"是否提取公共辅助代码"：生命周期程序与本程序共用约 90 行平台辅助
（`IsAsciiOnly`/`Widen`/`NormalizeWide`/`LoadedModulePath`/`CountFilesBeneath`）。
本轮选择**复制而非抽库**：抽一个静态库会为省 90 行引入第三条构建边和第二个需要
保持 CRT 一致的目标，收益为负。已在 `tools/rime_input_replay/CMakeLists.txt` 注释中登记该决定。

## 7. 干净运行与重复运行

【实测】**干净运行**：构建包装脚本带 `-Fresh`，删除 `build/librime-baseline/replay`
整个目录后重新 configure → build → 三轮 CTest（replay / lifecycle / root），
5 个步骤退出码全为 0，2+1+4 条用例全 Passed。

【实测】**重复运行**：不带 `-Fresh`（复用已有构建树）再跑同一序列，结果完全相同。

重复运行不依赖残留状态的直接证据：

```
编译产物 mtime（干净运行）: 2026-10-18 03:15:50.505  …/matrix/user/build/default.yaml
                          2026-10-18 03:15:50.515  …/matrix/user/build/epocanva_test_raw.schema.yaml
编译产物 mtime（重复运行）: 2026-10-18 03:16:23.313  …
                          2026-10-18 03:16:23.323  …
```

两次 mtime 不同 → 第二次运行**重新编译了配置**，没有复用上一次 staging。
机制上是程序在每次运行开头删除并重建自己的运行根
（打印 `run-root … (recreated empty)`），因此"不依赖上一次缓存"是构造保证。

两次运行的目录内容清单一致且只含测试数据：

```
matrix/shared/{default.yaml, epocanva_test_raw.schema.yaml}          夹具副本
matrix/user/build/{default.yaml, epocanva_test_raw.schema.yaml}      部署产物
matrix/user/user.yaml                                               Switcher::SetActiveSchema 的写入
missing-fixture/user/user.yaml                                      负向运行只有这一个文件，没有 build/
```

`missing-fixture` 下**没有** `user/build/` 目录，就是"什么都没部署成功"的磁盘证据。

如实登记的副作用：`select_schema()` 会经 `Switcher::SetActiveSchema`
（`src/rime/switcher.cc:165-172`）把
`var/previously_selected_schema` 与 `var/schema_access_time/*` 写进
`<user>/user.yaml`，无效 schema 的 id 也被写了进去：

```yaml
var:
  previously_selected_schema: epocanva_test_raw
  schema_access_time:
    epocanva_no_such_schema_p13: 1792264583
    epocanva_test_raw: 1792264583
```

写入位置是私有运行目录，**没有触碰用户现有 Rime 目录**；
但它说明一件事：**任何调用 `select_schema` 的路径都会持久化状态**，
后续阶段的测试隔离必须照此处理。

## 10. 下一步自定义组件接入的实际建议

先把**核实过的事实**摆在前面（都是本轮读固定提交源码所得，不是推测）：

* `Registry::instance()/Register/Find/Unregister` **确实带 `RIME_DLL`**
  （`src/rime/registry.h:21-26`），导出符号在 `DEFINE_SYMBOL "RIME_EXPORTS"`
  （`src/CMakeLists.txt:87`）下生效 → 树外模块理论上能把组件注册进同一个注册表。
* 但它们的签名是 `const rime::string&` 与 `ComponentBase*`，
  且 `component.h`/`registry.h` **不随 `INSTALL_PRIVATE_HEADERS=OFF` 安装**
  （安装出去的只有 4 个头，见 P1.2 §6.4）→ 客户端必须直接包含
  `third_party/librime/src/` 下的私有头。
* `rime-static` 只在 `BUILD_SHARED_LIBS=OFF` 分支才创建
  （`src/CMakeLists.txt:166-173`）。本轮基线是共享库，所以**没有**静态 rime 可用。
* 组件对象的 `new` 发生在注册方，`delete` 发生在持有 `an<>` 的引擎方。
  在 **/MT** 下两个模块各有自己的 CRT 堆 → 这正是跨边界分配/释放问题。

因此**三条可行路线，各有明确代价**：

| 路线 | 做法 | 代价 / 前提 |
| --- | --- | --- |
| A. 合入同一镜像（推荐先试） | 组件作为 librime 插件参与构建，`BUILD_MERGED_PLUGINS=ON` 时其 objects 与 rime 同库（`plugins/CMakeLists.txt:48-52`），需要 `RIME_SETUP_EXTRA_MODULES` 把模块名编进 `kDefaultModules`（`src/CMakeLists.txt:174-177`、`setup.cc:25`） | 上游插件目录机制要求插件目录位于 `third_party/librime/plugins/` 之下，即**在检出树里新增文件**，与"上游字节干净 + 树内 0 产物"的现状态冲突；需要一条 ADR 决定"插件源放哪、如何在不污染上游树的前提下接入" |
| B. 单一二进制静态链接 | 以 `BUILD_SHARED_LIBS=OFF` 产出 `rime-static`，把引擎与我们的组件链进同一个产物（TSF DLL 或测试 exe） | new/delete 与 `Registry` 都在一个模块内，**跨 DLL 所有权表（P1.2 §6.1）整张作废**，最简单；但产物形态改变，且失去"替换 rime.dll"的能力 |
| C. 共享 rime.dll + 动态 CRT | rime.dll 与适配层/插件统一 `/MD`，共享一个 CRT 堆 | 必须先解决 P1.2 §3.2 登记的发行策略未决项（VCRedist 随包），且 `std::string` 跨边界仍要求两边 STL/ABI 完全一致 |

**具体建议（按顺序）**：

1. **先出 ADR，再写组件**。上面三条路线会改变构建图与产物形态，
   属于 `docs/adr/` 的决策而不是实现细节。当前 `AGENTS.md` §8 与 P1.2 §3.2
   都把 CRT/发行策略标为未决，路线选择必须与之一并决定。
2. **P1.4 继续只用已注册组件**，把本轮链路当作回归基线：
   现在已能证明"按键→组合→提交"在真实 DLL 上成立，
   再加候选数、翻页、多段组合（`abc_segmentor` + 多个 translator 的 tag 路由）
   仍然不需要词典，也不需要任何上游改动。
3. **schema 可用性判断不要依赖 `select_schema()` 的返回值**（§7 第 1 条实测性质）。
   下一轮应改用 `get_schema_list()`/`free_schema_list()` 做可用性枚举 +
   `get_status().schema_id` 做回读 + 能否组合作为行为学证据；
   本轮没有调用 `get_schema_list`，**它是否能在只部署了夹具的目录里列出方案尚未验证**。
4. **保留本轮的运行目录隔离模式**：任何写 `user.yaml`、staging 的测试都必须
   在私有可重建目录内跑，并在报告里如实登记写入内容（§7）。
5. 若走路线 A/B，**上游仍不得就地改**：所有必需改动写成 `third_party/patches/*.patch`
   并在 `docs/build/bootstrap.md` 登记理由，同时更新 `sources.lock.json`
   的 `epocanva_build_adaptation_inputs` 语义（补丁与构建适配输入是两类东西，都要登记）。
