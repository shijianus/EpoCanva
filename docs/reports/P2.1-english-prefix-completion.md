## 2. 架构决定（按任务书第三节，未重新讨论）

沿用 P1.4 / ADR-0004 的**编译进引擎 DLL**方式：组件与 `rime` 目标同处一个 PE 模块，
注册发生在该 DLL 内，前端只用公开 C API，Release/x64/`/MT`，无独立插件 DLL，
`ENABLE_EXTERNAL_PLUGINS=OFF`，不改 `kDefaultModules`。

本轮**唯一**的结构新增是分两层：

| 层 | 目录 | 允许包含 | 禁止 |
| --- | --- | --- | --- |
| 语言核心 | `engine/languages/en/` | 仅标准库（`<string>` `<vector>` `<algorithm>` `<filesystem>` `<fstream>`） | `#include <rime/…>`、平台头、Session、历史、网络、写文件 |
| Rime 接入 | `engine/rime_components/english/` | librime 私有头（`rime/translator.h`、`rime/candidate.h`、`rime/translation.h`、`rime/segmentation.h`、`rime/config.h`、`rime/schema.h`、`rime/service.h`、`rime/deployer.h`） | 任何 `LOG`、任何每键文件 I/O |

理由：核心能在**根工程（Debug/动态 CRT）里单独编译并单测**，因为它不依赖 librime；
这使 §7 的 11 组单元测试不需要引擎、不需要 Release 构建、也不引入第二套 CRT 组合。
同一份源码由 `engine/languages/en/CMakeLists.txt` 里**一个源文件列表**同时供两处使用，
避免"测的与跑的不是同一份"。

**英文模式不编译探针组件**：`-Mode english-completion` 的
`EPOCANVA_RIME_COMPONENT_NAMES` 只有 `english`，
所以该 DLL 里**根本不存在** `epocanva_probe`，也没有任何 F6 行为——
不是"编译了但没装载"，是对象文件都不在链里。实测该 DLL 的 obj 集合是
113（baseline）+ 4（english）= 117，`probe_*.obj` 命中 **0**。

## 3. 决定接入方式前核实的事实（读自固定提交 `33e7814`）

| 事实 | 【源码】 |
| --- | --- |
| `Translator::Query(const string& input, const Segment& segment)` 是纯虚入口 | `src/rime/translator.h:26-28` |

**由这些事实得出的两个设计点**（不是偏好，是这些行号的后果）：

1. **原文由本组件放在候选 0，schema 里不列 `echo_translator`。**
   菜单里只有一个 translation 时顺序完全由 `FifoTranslation` 的追加顺序决定
   （`translation.cc:133-141`），所以"原文在前、补全在后"是**本组件控制的**，

   测试程序**必须**显式设置 `RimeTraits.shared_data_dir`，并在运行时读回
   `get_shared_data_dir_s` 与它比对（本轮实测输出见 §5.1 `shared_data_dir` 行）。
   这条断言就是这么来的，不是装饰。

## 4. 契约（含单位）

### 4.1 输入

`prefix_completer.h`：`kMaxPrefixBytes = 64`（**UTF-8 码元 = 字节**，因为字母表只有 `a`-`z`）。

| 输入 | 状态 | 行为 |
| --- | --- | --- |
| 空 | `kEmpty` | 空补全，不查索引 |
| `>64` 字节 | `kTooLong` | **不截断**，不补全 |
| 含非 `a`-`z` 字节（大写、空格、`-`、`.`、数字、任何 ≥0x80） | `kNotLowercaseAscii` | **不转小写、不 trim、不删字符**，不补全 |
| 合法但无命中 | `kOk`，`match_count=0` | 只有候选 0 |

组件侧：被拒绝的前缀计入 `queries_rejected`，仍然给出候选 0（原文），
**绝不**因为"看起来像 `Hello`"就悄悄按 `hello` 去补全。

### 4.2 词表 `word<TAB>weight`

| 条件 | 状态 | 是否报行号 |
| --- | --- | --- |
| 正常 | `kOk` | — |
| 0 字节 / 只有换行 | `kEmptyFile` | — |
| 中间空行（含文件末尾多余的一个换行） | `kBlankLine` | 是 |
| 没有制表符 | `kMissingField` | 是 |
| 两个以上制表符 | `kTooManyFields` | 是 |
| 词为空 / 含非 `a`-`z` | `kIllegalWord` | 是 |
| 词 > 64 字节 | `kWordTooLong` | 是 |
| 词重复 | `kDuplicateWord` | 是（报**后出现**那行） |
| 权重空 / 非数字 / 带符号 / 前后空格 / 前导零 | `kIllegalWeight` | 是 |
| 权重 > 4294967295 | `kWeightOverflow` | 是 |
| 路径不存在 / 不是普通文件 | `kFileNotFound` / `kFileUnreadable` | — |

LF 与 CRLF 均可；**文件末尾允许恰好一个换行**（它终止最后一条记录，不产生空行）；
没有注释语法、没有 BOM 容忍、没有字段内空白容忍。
`kEmptyFile`、`kFileNotFound`、`kFileUnreadable` 与 `kOk + 0 条`
是**四个不同的值**——"读不到"永远不会被表示成"读到了空词表"。
（本轮真实踩到这条：夹具初版带 `#` 注释行，加载器如实报 `missing-field`，
见 §8。）

### 4.3 排序与预算

1. weight **降序**；2. 同分按词 **ASCII 字节升序**。不用 locale/`strcoll`、不用时间、
不依赖无序容器遍历顺序。词唯一 ⇒ 比较器是全序 ⇒ `partial_sort` 结果确定。

区间定位用两次二分：`[lower_bound(p), lower_bound(p + '{'))`，
`'{' = 0x7B = 'z'+1`。正确性依赖"词的每个字节都在 `a`-`z`"这一由加载器保证的不变量，
`prefix_completer.cc` 顶部把这条推理写死了，不是靠试。

候选预算：总数 ≤ **8** = 候选 0 原文 + ≤ **7** 补全（`EPOCANVA_ENGLISH_MAX_TOTAL_CANDIDATES`）。
schema 里 `english/max_completions` **只能调低不能调高**（组件把请求 clamp 到 `[0,7]`）。
核心层 `kMaxCompletions = 64` 是另一个上限，防止误用调用方一次拷走整表。

### 5.6 这套测试能失败【实测，且已注册为常驻用例】

| 用例 | 组合 | 期望退出码 | 实测 |
| --- | --- | --- | --- |
| `positive_mode_fails_on_baseline_engine` | 组件 exe + **baseline** `rime.dll` + `--mode completion` | **20** | **20** ✅ |

要求套件返回 **1**（若 harness 吞掉了假断言则返回 3），实测 **1**。
`--expect-dll` 给相对路径时程序退出 **4** 并打印 expected/actual——本轮实测撞到过一次。

### 5.7 词表不是每键重载【实测】

一次 `completion` 运行注入 17 个字母键 + 2 次 Return + 1 次 BackSpace + 2 次 Escape，
跨 **2 个 session**，终局计数：

```
attempts=1 ok=1 entries=49 queries=18 with_index=18 xl_ctor=4 xl_live=0
```

`lexicon_load_attempts` 全程为 **1**，而 `queries` 为 **18**、
`translator_constructed` 为 **4**（session 建立与 `select_schema` 都会重建引擎）。
机制是 `EnglishLexiconCache` 以**规范化后的解析路径**为键、
`std::mutex` + `std::map<std::string, shared_ptr<const LexiconRecord>>` 缓存；
**失败结果同样缓存**，所以坏词表也只尝试一次（`missing-lexicon` 模式实测 `attempts=1`）。
文件 I/O 只发生在 `Acquire` 的 cache-miss 分支，`Query()` 里没有任何 I/O 调用。

### 5.8 小规模计时（不作性能结论）

`english.core` 的 `--bench`：14 行夹具、200 000 次 `CompletePrefix("a", 8)`，
合计 4 315 790 µs，**约 21.6 µs/次**（含每次返回值的 vector 分配）。
这只是代码形状的自检，**不是**生产规模数据，也**不是**与任何产品的比较；
词表 49 行、全部驻留在 cache 里。生产结论需要真实词库，本轮没有。

## 6. 本轮修掉的两个既有构建缺陷（任务书第十节点名）

### 6.1 增量构建因日志没有 `/MT` 而误报

原逻辑：`if ($mt -eq 0) { throw 'no /MT appeared…' }`。
`/MT=0` 有两种完全不同的原因：静态 CRT 真的没到编译器；**或者本轮根本没有源文件被重编**
（MSBuild 判定 up-to-date，日志里没有 cl 命令行）。后者被误判成失败——
这正是 P1.4 报告 §8 记录的那次 exit 1。

现在用**与日志无关**的观测量区分：本轮是否真的有 `.obj` 被写出来
（`LastWriteTime >= $script:RunStart`）。

- 有 obj 被重写而日志里没有 `/MT` → **仍然 throw**，消息带上重写条数；
- 没有任何 obj 被重写 → 不 throw，改为从已在上方逐件读过的 `dumpbin /directives`
  `MT_StaticRelease` 标签出结论，并打印"本轮重编 0 个对象，命令行抽样按构造为空"。

`/MD != 0` 依然无条件 throw；逐件 ABI 断言（依赖 .lib、`rime.dir` 抽样 obj、
4 个组件 obj、`rime.lib`、`rime.dll`）一条没删。
实测：`-Mode english-completion`（**不带** `-Fresh`、**不带** `-Verbose_Build`）
现在 **exit 0**，输出
`objects written by this run: 0 of 117` 与
`CRT certified instead from MT_StaticRelease directives on 11 artefact(s)`。
没有强制全量重编，也没有伪造日志内容。

### 6.2 `-Skip` 经 `powershell.exe -File` 不拆分

`-File` 把 `marisa,yaml-cpp` 绑定成**一个**数组元素，于是四个依赖一个都没跳过
（P1.4 报告 §8 末段撞到的就是这个）。现在把 `$Skip` 按逗号再拆一次、
`Trim`、去空、转小写，并且**拒绝未知名字**（原来会静默接受拼写错误）。

实测：`-Mode baseline -Skip 'marisa,yaml-cpp,leveldb,opencc,rime'` 经 `-File` 传入 →
**exit 0**，日志逐条打印 `skipping marisa / yaml-cpp / leveldb / opencc / rime`；
`-Skip 'marisa,typo-name'` → 报
`-Skip accepts marisa, yaml-cpp, leveldb, opencc, rime; got: typo-name`。
本轮**没有**任何模式需要 `-Skip`，这条只是把契约修对，未借此扩大构建重构。

## 7. 实现过程中真实发生过的失败（按要求记录，不粉饰）

1. **夹具带注释 → 加载必然失败。** 首版 `lexicon.tsv` 与两份负向夹具用 `#` 写了说明。
   加载器如实报 `missing-field`（注释行没有制表符），补全全部退化成只有原文。
   副作用更阴险的是行号漂移：`bad-duplicate` 的"第 3 行"变成了第 1 行。
   修法：三个 `.tsv` 改为**纯数据**，说明搬进夹具 README，并在 README §3 写明
   "这里不许有注释"的原因。
2. **`traits.modules` 被我写成只有自有模块 → 部署失败。**
   `deploy_config_file`/`deploy_schema` 需要的任务组件由 `levers` 提供
   （`levers_module.cc:20-31`），`default` 提供 core/dict/gears。只列自有模块时
   四个部署断言全红。修成 `{"default", "levers", "epocanva_english"}`
   （与 P1.4 程序一致）。**负向用例没受影响**：baseline 引擎同样列这三个名字，
   自有那个找不到就被跳过——这恰好是 ADR-0004「限制」2 的行为学证据。
3. **我自己两处手工推导错误。** `ab` 前缀漏了 `about`；`app` 前缀漏了 `apply`。
   都是**代码对、我的期望错**。按任务书要求期望必须独立手写，所以我改的是期望值
   并在夹具 README 里把推导补全，而不是把断言删松。
   （同一条纪律在 P1.4 复验里也用过：那次是报告行号失实。）
4. **测试包装件的 `string(FIND … "")` 恒命中。** 空 needle 在任意输入里偏移都是 0，
   导致 8 条用例里凡是"禁止 marker"的三条**必然失败**。改成
   `MARKER_POLICY=require|forbid` + 非空 `MARKER` 常量。
5. **marker 字面量的空格数不可靠。** 我最初打的是列对齐的 `RESULT······PASS`，
   而包装件找连续的 `RESULT PASS`，差 19 个空格就永远匹配不上。
   改成与 `tools/toolchain_probe` 一致的连续 `RESULT PASS` / `RESULT FAIL`。
6. **PowerShell `-f` 优先级**：`"a {0} " + "b" -f $n` 只对 `"b"` 做格式化，
   `{0}` 原样打印。三处（ATTACHED throw、CRT 认证消息、cl 计数消息）都补了外层括号，
   并在 §6.1 那条输出里留下了修正前的真实证据。

## 9. 未完成项与已知风险
