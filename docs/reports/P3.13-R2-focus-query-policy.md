## 1. Explicit thread-focus policy

`ThreadFocusPolicy` is now a required constructor argument of `ContextObserver`:

| Policy | Behaviour |
| --- | --- |
| `StrictTsf` (product default) | TSF notification or successful `IsThreadFocus == TRUE` only. `GetGUIThreadInfo` is never probed. |
| `LabWin32Fallback` (lab/test only) | The above, plus a real Win32 focus window when `IsThreadFocus` itself **succeeded with FALSE** (the lab's `S_FALSE`). A failed query is never rescued by the fallback. |

The fallback is not inferred from a registry entry, a window's existence, or a failed query.
The lab constructs its observer with `kLabWin32Fallback` explicitly; the new
`focus_guard_strict_no_fallback` integration case proves that a real Win32 focus window is
neither probed nor accepted under `StrictTsf`.

## 2. Failure classification and preserved evidence

`TargetEvidence` now keeps the real answer of each call:

* `thread_focus_query_ok`, `thread_focus`, `thread_focus_query_hr`;
* `get_focus_hr`, `get_top_hr`;
* `registry_query_ok`, `registry_status`;
* `ThreadFocusPolicy policy`.

`TargetRevalidation::failure_stage` names the deciding API when the status is
`QueryFailed`. `query_hr` is the deciding HRESULT. A successful empty result is not an
error:

| Fact | Status | Stage | `query_hr` |
| --- | --- | --- | --- |
| `IsThreadFocus` failed | `QueryFailed` | `thread-focus-query` | actual HRESULT; BOOL invalid |
| `IsThreadFocus` succeeded, FALSE | `ThreadFocusUnconfirmed` | `none` | `S_OK`; BOOL valid FALSE |
| `GetFocus` failed | `QueryFailed` | `get-focus` | actual HRESULT |
| `GetFocus` succeeded, no manager | `NoDocumentManager` | `none` | `S_OK` |
| `GetTop` failed | `QueryFailed` | `get-top` | actual HRESULT |
| `GetTop` succeeded, no top | `NoTopContext` | `none` | `S_OK` |
| registry non-Ok | `QueryFailed` | `registry` | `E_FAIL`; status enum in evidence |
| real top/identity mismatch | `ContextMismatch` | `none` | `S_OK` |
| generation mismatch | `GenerationMismatch` | `none` | `S_OK` |
| kill notification | `ThreadFocusLost` | `none` | `S_OK` |

The coordinator's `last_target_revalidation` remains a copy of that decision. The lab's
“Last refusal” line renders the preserved stage, target status, source, query HRESULT,
thread-focus BOOL validity/value, Win32 flag, `GetFocus`/`GetTop` HRESULTs and registry
status. The live thread-focus line is labelled as live and is not the refusal snapshot.

## 3. Rejection paths

### Path A — notification first (real TSF delivery)

`windows.tsf_coordinator.focus_notification_before_guard`:

1. A key is accepted on A and its engine dispatch is held.
2. A real `OnPushContext` in A's document manager drops the target.
3. `OnTargetLost` retires A; the coordinator is unbound, the work is `AbandonedStale`, the
   engine request moves into the retirement ledger, and the guard count is unchanged.
4. A submit while unbound returns `NotBound`, creates no work, makes no engine call and
   writes nothing.
5. The held engine result is consumed exactly once and discarded; exactly one close is
   submitted and consumed; no retirement fact is unresolved.
6. The parent context is rebound with a newer generation; only fresh input is applied. The
   old key is not replayed.

`observed_late_edit` is the same shape through a target loss detected before the late edit
grant: the retired session runs no target guard and makes no live target query.

### Path B — execution-time revalidation (controlled ordering)

`windows.tsf_coordinator.focus_revalidate_before_notification`:

1. A test-only `ContextObserverSink` gate is installed; it forwards binds/own edits and
   buffers `OnTargetLost` only while the test enables deferral.
2. A real `SetFocus` moves the TSF target to B. If msctf delivers `OnSetFocus`, the observer
   counter increases and the gate holds the loss; the controller binding and coordinator
   remain current.
3. `SubmitKey` runs the live guard exactly once. It reads the real `GetFocus`/`GetTop`
   mismatch and returns `TargetChanged`; no engine call and no document write.
4. The gate releases the held loss, the observer re-reads the current target, and B is
   rebound. The refused key is not replayed.

This is controlled timing, not a real-notification verification; the log separately records
whether the real notification arrived. Product code has no “ignore notifications” switch.

## 4. Mapping of the original six cases

All branches are selected by call-order evidence (guard count, callback count, real
notification counters), never by the final outcome.

| Case | Mapping | Evidence kept |
| --- | --- | --- |
| `observed_late_edit` | Path A | invalidation before the late grant; retired session has 0 target callbacks and 0 live queries; no write/replay |
| `focus_guard_submit_target` | A or B (guard count) | B: guard +1, `ContextMismatch`, no notification; A: guard unchanged, `NotBound`, loss notification |
| `focus_guard_engine_target` | A or B (result-time guard count) | B: +1 guard, `NeedsResync`; A: `AbandonedStale`, result discarded once, client closed once |
| `focus_guard_edit_target` | A or B (granted-callback count) | B: callback +1, `TargetChanged`, no write; A: callback unchanged, stale retired session |
| `focus_guard_thread_lost` | A or B (guard count) | B: +1 guard, `ThreadFocusUnconfirmed` (valid FALSE BOOL); A: real `OnSetFocus(NULL)`/kill notification, no guard |
| `focus_guard_foreign_dm` | A or B (guard count) | B: +1 guard, branch on the independent foreign `GetTop` result (`ContextMismatch` / `NoTopContext` / `QueryFailed`); A: real `OnSetFocus` loss |

In the final five focused rounds this environment delivered `OnSetFocus` (and
`OnSetFocus(NULL)`), so all five `focus_guard_*` cases took their path-A branch; earlier
runs in the same session took path B (for example `build/p313-r2-pathB-r1.log` and
`build/p313-r2-case-focus-guard-engine-target-r1.log`). The deterministic path-B guard is
covered by the controlled gate case above and by `focus_guard_strict_no_fallback`.
