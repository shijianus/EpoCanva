## 3. Design choices and rejected alternatives

**Live target authority, not a cached boolean.** `ContextObserver` implements
`TargetRevalidator`. Its check reads `ITfThreadMgr::IsThreadFocus`, the thread-focus sink
state, `GetGUIThreadInfo` (lab fallback), `GetFocus`, canonical `GetTop`, and the registry
id/generation. Rejected: treating a non-null `GetFocus` as proof of focus; it does not say
whether this thread owns input focus.

**`GetForegroundWindow` is not an admission input.** It is displayed in the lab for
observation only. Rejected: using it as the universal TSF-focus substitute; it is neither a
TSF statement nor sufficient when the TSF thread and the foreground window differ.

**The thread-focus sink is advised, not synthesized.** `ITfThreadFocusSink` is advised on
the thread manager's `ITfSource` and unadvised with the same cookie. Tests assert paired
advice/unadvice and COM reference balance. No test calls the sink methods directly to fake a
system notification.

**Callback-time live recheck.** The P3.7 session checks the target before requesting a lock
and again inside `DoEditSession` with the granted cookie, before the permission recheck or
any write. Rejected: relying only on a notification epoch; a focus change during a deferred
lock could otherwise slip through before the observer pumps. A `TargetWriteGuard` holds a
weak observer state, so a post-shutdown callback refuses instead of dereferencing a stale
pointer.

**Cleanup is exempt but not weakened.** `EndOwnedComposition` skips the target check because
it is legal on an old, unfocused context the writer owns. Every P3.12 ownership, range,
permission, read-only and Uncertain check remains. Rejected: blocking cleanup on focus loss,
which would leave owned compositions behind, and reusing the normal edit path, which could
write text.

**No replay.** A refused target, key, candidate or commit is discarded. After a
`Retiring`/`Busy` refusal the controller records `rebind_pending` and creates no client;
once the retirement ledger is terminal it asks the observer to re-read the **current**
`GetFocus`/`GetTop`. Rejected: replaying the refused target id or creating a client before
admission.

**No unchecked product path.** `BindObserved` requires a target authority; `SubmitKey`/
`SubmitCandidate` refuse as `TargetUnverified` without one. The direct `Bind()` unit seam is
kept for controlled state-machine cases, but those cases attach a test-owned
`TestTargetRevalidator`; the real observer integrates through `ObservedBindingController`.
Rejected: an implicit "no guard means allow" mode.

## 5. What is not verified

* **Manual clicks are pending.** The user must run the command in
  `docs/windows/focus-acceptance-checklist.md` and fill in the steps. This report and the
  screenshot are automated evidence only.
* **No `OnSetFocus` or thread-focus notification was observed** in this environment. Bind
  evidence is `revalidation`; `notify_set=0`, `notify_kill=0`. The focus sink is advised and
  its advice/unadvice balance is asserted, but actual delivery is untested here.
* **`ITfThreadMgr::IsThreadFocus` is `S_FALSE`** in the non-registered lab process. The
  guard records it and uses the labelled `win32-thread-focus-revalidation`. A registered TIP
  in a normal host is expected to use the TSF query/notification path, but that is not
  exercised in this phase.
* **Null/empty TSF focus cannot be held** in this environment: `SetFocus(nullptr)` is
  restored to the associated document, and a new empty document manager receives a top
  context. The no-document-manager/no-top decisions are covered by the pure and controlled
  tests, not by a real focused null/empty state.
* **The lab still submits only fixed fixture input.** There is no natural keyboard path, no
  registration, no candidate window, no key sink and no external-application write.
* **The Windows offline guarantee is architectural**, not an OS sandbox. The Android
  `INTERNET`-omission statement is separate and untouched.
* A long interactive session can still reach the bounded retirement ledger; the ledger
  refuses rather than grows, and the UI shows `Retiring`/`rebind_pending`. No automatic
  retry of a refused key exists.

## 6. Blockers before the next phase

No code blocker for the P3.13 scope. The next phase must not treat this lab as a registered
input method or claim manual acceptance before the checklist is returned. A future
registration/key-sink phase must re-run the TSF focus-sink path with an actually activated
TIP and verify that `OnSetThreadFocus`/`OnKillThreadFocus` and `OnSetFocus` are delivered in
that host, because this round could not produce them.
