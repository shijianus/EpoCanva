# Japanese lexical decoder verification

`engine/japanese_decoder` is a project-authored bounded k-best Viterbi decoder over actual Mozc OSS dictionary readings, surfaces, left/right POS IDs and word costs. It is not the full Mozc input method or all Mozc rewriters. Romaji composition remains the existing separate `engine/languages/ja` component.

The reviewed source snapshot is `google/mozc@e5f1494923a0a624d01f19c50d57bbdfa03ea5ba`. The official source proves transition indexing as previous right-ID row / current left-ID column (`src/data_manager/gen_connection_data.py:76-93`; `src/converter/nbest_generator.cc:747-755`; `src/converter/connector.cc:342-353`). The first connection-file line is dimension2672 followed by exactly2672² values, not an extra BOS dimension. Separate source notices and provenance are recorded in `data/manifests/backend-ja-corpus.sources.json`.

`tools/data/compile_mozc_lexicon.py` produces a little-endian `EPCJA01` resource containing the exact connection matrix and1,289,076 lexical rows. The observed artifact is73,919,277 bytes, SHA-256 `e0308bb1e09e33915a40ca487ca3c27081d9564876f655a23fb332e2d6b3d011`. No model weights or source dictionaries are committed as code. The converter preserves surface/reading/IDs/costs; optional sixth metadata fields are not interpreted, and its output does not claim equivalent Mozc rewrite behavior.

Runtime validates the pinned local file digest, UTF-8, counts, IDs and bounds. The index is a sorted immutable reading table; each input substring is binary-searched, not a full corpus scan. States are keyed by original reading UTF-8 byte boundary and right POS ID. Per-state k-best paths retain distinct outputs; final EOS connection costs are applied. A hard200,000-transition limit produces explicit budget status. Unknown valid kana is a marked fallback, not a dictionary word. `resident_bytes()` is representation accounting, not process peak RSS or allocator overhead proof.

Actual Release test loaded the production dictionary and passed Kana→Kanji probes (日本/私/学校), a multi-entry composed path, UTF-8 input spans, protected non-kana rejection and wrong-resource-hash rejection. Its first loading attempt failed because a reused generic product helper capped files at64MiB; the decoder now reads within its explicit256MiB source bound and hashes the exact bytes. The API later passed actual five-language headless selection/commit smoke testing. These are functional tests, not a native-language conversion-quality benchmark, memory admission, or broad grammar claim.

All resources and tests remain offline after explicit acquisition. No user input logging, learning files, network I/O or source checkout edits are introduced. Full phrase prediction, unknown-word strategy, broader benchmark coverage and distribution/source-reconstruction proof remain separate gates.
